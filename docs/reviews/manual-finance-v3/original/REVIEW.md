**Исходный SHA `main`:** `461a11e0dd28824eb1483930788447a1df33a835` (свежий клон после нормализации авторства).
**Окружение:** Python 3.11.14, зависимости строго из `requirements.lock` (`--require-hashes`): tzdata 2026.6, duckdb 1.1.3; Windows 11.
**PR GPT Pro 1 по #13 на момент проверки отсутствует** (открыт только PR #20 про Docker; `feature/simulator` старее `main`). Поэтому проверен генератор 1.3 из `main`, принятый в PR #12. Код не менялся, PR не создавался.

## Порядок работы (что фактически сделано)

1. Реальным `generate_episode` (main) созданы 10 новых эпизодов `config_version: "1.1"` с малыми seed 7101–7109, не пересекающимися с опубликованными 128-битными seed train/dev.
2. Для ручного расчёта скопирован только `public/`. Ответ посчитан вручную по строкам: Python использовался только для показа таблиц и как калькулятор. Код генератора и verifier для ответа не использовался.
3. Ответ записан в `manual_before_truth.json`, SHA-256 `84f61ae3e14dc479a1ff5410e8595dd951dbf4186ba2bb51815d1c832dc5c032`, закоммичен локально (`e09d4aa`, автор jegrud). Только после этого были открыты `private/truth.json` и `provenance.json`.
4. После этого: сравнение с truth; оценка ручного ответа настоящим оценщиком; проверка выдачи каждой ссылки эталона через `open_session(...).inspect`; прогон обычного `reconcile` через runner; verifier как отдельная перекрёстная сверка.

Хеш подтверждает идентичность файла, но сам по себе не доказывает хронологию. Порядок подтверждается локальной историей коммитов: ответ закоммичен до первого чтения truth.

## DAT-01: исходная чистая книга до мутации

**Не подтверждена, потому что не предоставлена.** `private/provenance.json` содержит конфигурацию, события и для каждой мутации поля `before`/`after`, но не полный снимок книги до мутации. Проверено только то, что есть: все 15 значений `before` совпадают с моим независимым ручным расчётом правильных величин. Примеры: 2 000 000 и 23:59 (C2/C3b); 1 862 950 по 503,50 (C4); 2 303 450 по 500,75 (C5); 821 по 8,55 (C6a); 153 690 по 1,090 (C6b); 100 800 по 6,30 и 2 000 000 к 31.10 23:59+01 (C7a); 20 124 по 1,29 (C7b). Для `duplicate_invoice` значение `before` указывает журнал исходного признания. Чтобы закрыть DAT-01 полностью, генератор должен публиковать в private полную исходную книгу (или её хеш с воспроизводимой реконструкцией).

## Ограничения (явно)

- Компании малые (`ledger_rows_target: 0`, 4–28 строк). Полноразмерные 200–2000 строк в этой проверке не пересчитывались вручную.
- Один seed на сценарий. Точная половина при округлении (…5) в этих примерах не встретилась (C6a: 820,8855). Граничное half-up ранее проверялось отдельно, здесь не повторялось.
- Переход летнего времени: проверены граница периода и даты курса по обе стороны перехода. События внутри пропущенного или повторного часа (02:00–03:00 в день перехода) не генерировались и не проверены.
- Не проверено: побайтовая сохранность train/dev 1.0, канонические близнецы семейств между train/dev/internal, `reconcile` после ID/order-преобразования. Это пункты GPT Pro 1 в #13. Внутренний F1/награда не являются конкурсным баллом.
