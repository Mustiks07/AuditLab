База `daf1fc64df37651e14801e0286b9741b30820d35`, генератор 1.5, профиль 1.1. План записан до запуска собственных новых выборок. Источником гипотез были код, прежние исследования и сообщения агентов. Новые входы являются инженерной проверкой. После публикации они открыты.

- 16 заранее выбранных seed `82460601..82460616`. Для каждого seed четыре изолированные серии `duplicate_invoice`, `payment_allocation`, `period_cutoff`, `fx_conversion`. В каждой ровно два состояния 0 и 1 при равных прочих настройках, всего 128 снимков на версию. Все KZT/USD, UTC, ноябрь 2028, 240×76, стандартные отвлекающие случаи.
- Второй блок `82460701..82460708`, 16 снимков 240×76 с явным `next_day_settlement`, KWD/KZT, Asia/Kathmandu, февраль 2028, 0/1 `payment_allocation`. Это отдельная проверка уточнённого признака, включая три десятичных знака.
- Предикторы фиксируются до прогона. Архивные группы в первичке минус один оценивают число дубликатов. Документные кандидаты на незачёт: выдан счёт, через сутки один платёж, индекс двух движений, добавляется сумма не кратна 1 000 целых единиц **или** ненулевая минута. Для периода предиктор помечает все положительные AR-признания с даты исключающей границы. Для FX счётчик строк `FX_VALUATION` минус один оценивает число FX-ошибок. Предикторы не обращаются к `truth`, не сверяют проводки с суммой документа, назначение или дату признания с датой источника.
- Порядок для каждого снимка: посчитать признаки только по public, после этого открыть truth для TP/FP/FN или сравнения счётчиков. Обычный `reconcile` проверяется отдельно через свой публичный интерфейс, без разметки в политике. Сравнить те же входы на исходном и изменённом коде. Изменения принимать по двум противоположным финансовым исходам при том же простом признаке, а также по независимому SQL на новых случаях и сохранности legacy. Баллы F1 не используются для отбора seed.
- Малые воспроизводимые пары — seed `82460601` из первой серии и `82460701` из второй. Другие диапазоны, модели и закрытые случаи жюри остаются вне этого измерения.
