# Независимая проверка шаблонов генератора, v2

База свежего клона и `origin/main` на начало проверки — `daf1fc64df37651e14801e0286b9741b30820d35` (генератор 1.5, RC3 уже опубликован). Исследование и правки находятся в `review/generator-adversarial-v2`. Кандидат — генератор **1.6**, финансовый профиль 1.1, SHA кода `725ba5cf2392aa007c6f3e3b4aee16207d674052`. Legacy-профиль по-прежнему записывает версию генератора 1.1. План и seed зафиксированы в `e066e35`.

**Вывод.** Прежние чистые примеры показывали принцип финансовой сверки, но на обычной конфигурации количество архивов и валютных оценок само кодировало число дефектов. Отдельные платежи можно было находить по точности суммы и времени. Любое признание после границы периода было ошибочным на проверенной базе. На 1.6 эти признаки дают одинаковый результат на противоположных финансовых состояниях или ложные обвинения. Закрытая проверка жюри и класс произвольных классификаторов остаются за пределами исследования.

## Что проверялось

Проверки относятся к SPEC §§4–6, 10–12 и 14 (DAT-01/02/04/05 и REP-03). Предыдущие работы уже покрывали 500 пар целых книг, точные коммерческие подистории внутреннего набора, генерацию чистых книг, округление FX и простой признак «два движения + сутки». Здесь проверяются новые комбинации признаков и новые диапазоны seed. Общая бухгалтерская схема, равная сумма в двух действительных счетах и общий порядок двойной записи сами по себе ничего не говорят об утечке. [Исходные исследования](../generator-1.5.md) · [Подистории](../subhistories/README.md) · [Стресс-проверка](../stress-2026-11-20/README.md) · [Ручная проверка](../manual-finance-v4/README.md)

Подозрения выводили из кода и проверяли на заранее записанных настройках. Предикторы получают только поля public. Trusted-сравнение открывает truth после создания предикта. Ни политика `reconcile`, ни её источники не изменены. Схема 1.0, контракты действий, evaluator, версии правил и список зависимостей сохраняются. Повторы одного чистого состояния в разных парных сериях учитываются как повторы, а не как независимые компании. [Запечатанный протокол](PROTOCOL.md)

## Собственные измерения GPT Pro 1

Заранее зафиксированы seed `82460601..82460616` для 128 парных снимков типового профиля и `82460701..82460708` для 16 снимков KWD/KZT с явным контрпримером. По каждой подсказке сравнивались одинаковые конфигурации в состояниях 0 и 1. Ни один seed не отбирался по качеству обычной политики. Наборы из новых диапазонов не выдаются за закрытый тест организатора.

| Признак без финансовой сверки | Генератор 1.5 | Генератор 1.6 |
|---|---:|---:|
| Число групп архивных копий минус один | 32/32 точных счётчиков | 0/32. Шесть групп при 0 и 1 дефекте |
| Число строк `FX_VALUATION` минус один | 32/32 точных счётчиков | 0/32. Девять–одиннадцать, точное равенство внутри каждой из 16 пар |
| Связанный платёж через сутки, две записи индекса, плюс некруглая сумма или ненулевая минута, KZT | 16 TP / 0 FP / 0 FN | 16 TP / 176 FP / 0 FN |
| Та же эвристика с ранее добавленным `next_day_settlement`, KWD | 8 TP / 0 FP / 0 FN | 8 TP / 88 FP / 0 FN |
| Положительное признание AR на границе или после неё | 16 TP / 0 FP / 0 FN | 16 TP / 192 FP / 0 FN |

Здесь TP/FP/FN считаются по сущностям. Счётчики архивов и оценок сравниваются на уровне снимка. Собственные результаты получены на двух зафиксированных версиях и сохранены как [исходные наблюдения](root-baseline.json) и [повтор на 1.6](root-candidate.json). SHA-256 исходного протокола — `fee0a1020511b9ebd00d55afa402b449f787a99b5bed568796a4f0b573c057cc`.

Собственный анализ кода связал признаки со способом генерации. Версия 1.5 добавляла первичку архивной пары и дополнительную оценку по одному на заказанный дефект. Чистый платёж следующего дня подбирался из суммы, кратной 1 000 целых единиц, и времени с минутой 00. Признание после периода не имело чистого соседа. Фоновый журнал казначейства начинался с числа уже запланированных строк, выраженного в секундах. Замена этого смещения фиксированной отправной точкой убрала прямое чтение длины префикса по времени. Число казначейских строк ещё может отражать доступный бюджет.

Для содержательного контрпримера возьмём seed `945606200`. На 1.6 платёж `payments/D761231F6643FEA796AD18D72` на 5 070 000 тиын имеет прежние время, документ и два ID движений в чистом и ошибочном случае. В `ledger/R82F279890CE7EA1E96C62A7F` кредит 5 070 000. Дебет `ledger/R0F6D581420DAC8F76E2A08F3` равен 5 070 000 рядом с чистым исходом и 3 042 000 рядом с ошибочным. Остатки 0 и 2 028 000 тиын (20 280 ₸) следуют из проводок. У архивной пары того же seed номинал 2 144 800 тиын и одинаковые два документа. Повторное признание меняет остаток с нуля до 2 144 800 тиын, хотя число архивных групп равно шести в обоих состояниях. [Структурное исследование](structural-notes.md)

## Обязательные исправления в PR

1. **Фиксированные пулы сравнимых операций.** На полной конфигурации шесть архивных групп и шесть самостоятельных оценок имеют одинаковую первичку при 0/1/5 заказанных ошибках. Самостоятельные платежи при `split_payment` или `next_day_settlement` формируются из общего пула. У чистого зачёта перечислена вся сумма, у ошибочного — только часть. Документы, даты, номиналы и индекс остаются одинаковыми. Разница в двух сторонах зачёта отражена в переходе от исходной книги.
2. **Подлинный контекст у границы.** Чистые счета соседнего периода признаются там же по первичному документу. У валютного взаимодействия есть одинаково построенные чистые счета перед границей и после неё, в том числе при обычной конфигурации без заказа связанной ошибки. Число чистых будущих проводок варьируется по seed. Законная пакетная проводка может быть позже времени счёта в том же периоде. Дата ставки FX сохраняется по источнику, включая законную задержку и ошибочную отсечку.
3. **Независимость формы от строки источника.** ID добавленных проводок выделяются отдельным потоком. Изменение числа строк в журнале не перемешивает одинаковую первичку. Для случая 240 строк / 76 документов с пятью дубликатами регрессия обнаружила рост до 248 строк. Необязательные разбивки и часть открытых счетов без платежа подбираются с запасом под все допустимые дубликаты. На 0/1/5 дубликатах тест получил 240/76 при побайтно одинаковой первичке. Для несовместимых малых targets манифест по-прежнему отражает фактическую книгу.

Содержательная регрессия проверяет денежные результаты по обычным публичным действиям и отдельно через SQLite. Сохранены требования к исчерпывающему индексу, перемене одного влияния в парных состояниях и валидации оригинала до применения мутации. [Тест пула и отсечки](../../../tests/simulator/test_adversarial_controls.py) · [Публичные правила](../../INTERFACES.md)

## Полезные улучшения

Внесены больший диапазон денежных сумм в младших единицах и вариация минуты фоновых событий при неизменном правиле. Это расширяет пространство чистых историй, сохраняя настоящие равные суммы и полный зачёт. Сходство тех же правил после обезличивания ожидаемо. Уменьшение точных повторов проверяется только на зафиксированных выборках.

Следующий отдельный эксперимент — раннее признание счёта следующего периода внутри текущего, включая контрольную пару и противоположное направление к действующему позднему признанию. Это позволит тестировать аудитора, который проверяет только переход «вперёд». Ещё один полезный отдельный сценарий — реальное событие внутри повторяющегося часа DST с двумя смещениями; включение месяца перехода само по себе его не создаёт. Оба потребуют независимого расчёта по public до сравнения с truth.

## Неподтверждённые идеи и пределы

- Вероятностные признаки по казначейскому объёму, многошаговый поиск близких графов, модель на всех публичных полях и перенос на незнакомые параметры не измерялись. Хеш полного содержимого может различать два фактически разных снимка. Здесь не проверялось угадывание низкоэнтропийного seed по известной конфигурации.
- Диагностические конфигурации могут явно отключить похожие чистые случаи. Например, `clean_distractors: []` оставляет без контрпримеров самостоятельный cutoff даже при 2 000×200, а также отключает фоновый архив и самостоятельный FX-пул. Результаты конфигурации по умолчанию на этот режим не распространяются.
- Вариации описаний коммерческих позиций и имён, больше одного назначения на платёж, локальные часовые пояса с переходом внутри периода и иной процент неполного зачёта полезны только как отдельные эксперименты с верифицируемыми правилами. В этой ветке обычная политика и общий контракт не расширены.
- Изоляция Linux/Docker, холодный выпуск и закрытая проверка организатора не выполнялись. Внутренние метрики не пересчитывались в баллы. Релизный тег RC3 относится к своему SHA, а внутренние артефакты 1.5 не следует сравнивать побайтно с вновь генерируемым профилем 1.1. Для кандидата интегратору нужны новые зафиксированные измерения.

## Команды для интегратора

Из корня клона с установленными зависимостями и каталогом `artifacts`. Каталоги вывода скриптов должны быть новыми. Первая команда с `--source` читает отдельно распакованный `git archive` исходного SHA.

```text
git archive --format=zip --output=artifacts/generator-1.5.zip daf1fc64df37651e14801e0286b9741b30820d35
# Распаковать архив в artifacts/generator-1.5.
python docs/reviews/generator-adversarial-v2/root-probe.py --source artifacts/generator-1.5 --output artifacts/root-1.5.json
python docs/reviews/generator-adversarial-v2/root-probe.py --output artifacts/root-1.6.json
python docs/reviews/generator-adversarial-v2/family-probe.py --output artifacts/family-1.6.json
python docs/reviews/generator-adversarial-v2/family-probe.py --signed-followup --output artifacts/family-signed-1.6.json
python docs/reviews/generator-adversarial-v2/scenario-probe.py threshold artifacts/cutoff-threshold
python -m unittest discover -s tests/foundation -v
python -m unittest discover -s tests/simulator -v
python -m unittest discover -s tests/verifier -v
python -m unittest discover -s tests/metamorphic -v
python -m unittest discover -s tests/runner -p test_public_schemas.py -v
python -m unittest discover -s tests/integration -p test_components.py -v
git diff --exit-code daf1fc64df37651e14801e0286b9741b30820d35 -- datasets/open
```
