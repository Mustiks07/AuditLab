# Пакет для независимого получателя: AuditLab v0.1.0-rc.3

Вы получаете готовый офлайн-архив AuditLab и проверяете его **сами, без подсказок авторов**. Ваш отчёт —
единственное, что может закрыть пункт OPS-02 (#15). Проверки разработчиков и AI-агентов его не заменяют.

## 2. Требования

- Linux x86_64. Windows и Docker Desktop не заявлены.
- **Python ровно 3.11** (`python3.11 --version`). Другие версии launcher отклоняет.
  В Ubuntu 24.04 по умолчанию 3.12, поэтому 3.11 ставится заранее, отдельно от проверки.
- Docker Engine с локальным сокетом `/var/run/docker.sock`; команда
  `docker --host unix:///var/run/docker.sock info` должна работать от вашего пользователя.
- Для подтверждения лимитов ресурсов нужна **cgroup v2**. На v1 функциональная проверка проходит, но коды
  возврата будут 2: это ожидаемо.
- Минимум 2 CPU и около 2 ГБ свободного диска (у агента заняло около 1,3 ГБ: ZIP 316 МБ, распакованный
  комплект с результатами 397 МБ, образы 468 МБ), браузер для консоли.

## 3. Порядок действий

Подробная инструкция с ожидаемыми выводами — [docs/demo/HANDOFF.md](../../demo/HANDOFF.md).
Чек-лист для отметок — [ACCEPTANCE_CHECKLIST.md](../../demo/ACCEPTANCE_CHECKLIST.md).
Сценарий консоли — [DEFENSE.md](../../demo/DEFENSE.md). Последовательность:

1. Запишите окружение (HANDOFF §1–2).
2. Проверьте хеш и распакуйте архив в пустой каталог `bundle` (HANDOFF §3).
3. Выполните `check`, `verify --suite quick`, `verify --suite rehearsal` и evidence checker (HANDOFF §4).
   Во втором терминале запишите `docker events`.
4. Прогоните обязательные политики на 10 train и 10 dev (HANDOFF §5а).
5. Прервите один `verify` сигналом и повторите запуск (HANDOFF §8).
6. Запустите консоль и пройдите сценарий DEFENSE.md в браузере, засекая время (HANDOFF §6).
7. Заполните [журнал](JOURNAL_FORM.md) и отправьте его владельцу проекта вместе с каталогом `results/`
   (или архивом `results/verify-*/launch.json`, `verify/report.json`, `evidence-summary.json`) и снимками
   экрана.

Ожидаемая длительность: подготовка 10–15 минут, проверки 15–25 минут машинного времени, консоль 5–10 минут.

## 4. Правила

- Не устанавливайте пакеты проекта, не собирайте образы, не скачивайте образы из registry, не подменяйте
  архив исходным кодом из репозитория.
- Если застряли, сначала запишите затруднение в журнал: время, команду, точный вывод. Если всё же обратились к
  авторам, отметьте это в журнале: кому, что спросили, что ответили. Проверка после подсказки остаётся
  засчитанной, но подсказка становится найденной проблемой инструкции.
- Не удаляйте чужие контейнеры и образы. Не меняйте рабочий Docker-демон с чужими контейнерами.
- Не делайте выводов о конкурсных баллах. Внутренние награды и F1 — диагностика одного набора.
- Снимки экрана не должны содержать ваших персональных данных: имя пользователя в приглашении терминала,
  e-mail, чужие вкладки браузера.

## 5. Что вернуть

Заполненный [JOURNAL_FORM.md](JOURNAL_FORM.md), каталог результатов или указанные файлы, вывод
`evidence-summary.json`, снимки консоли. Формулировка вывода: «независимая человеческая проверка комплекта
v0.1.0-rc.3 на машине …», без утверждений о баллах. Владелец проекта добавляет журнал в
`docs/reviews/receiver-acceptance-rc3/HUMAN_JOURNAL.md` без правок по существу.
