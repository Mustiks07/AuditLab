# Приёмка получателем v0.1.0-rc.3: отчёт

**Итог.** Агентская проверка опубликованного архива RC3 по инструкции получателя прошла на обоих хранилищах
Docker. Найдено и исправлено в этой ветке 9 проблем интерфейса и инструкции, одна оставлена владельцу runner.
**Независимый человек инструкцию не проходил**: в этой сессии такой человек недоступен. Поэтому OPS-02 и
Issue [#15](https://github.com/Mustiks07/AuditLab/issues/15) остаются открытыми. Не хватает одного действия:
владелец проекта передаёт [пакет получателя](RECEIVER_PACKAGE.md) человеку, не участвовавшему в разработке,
и добавляет его заполненный [журнал](JOURNAL_FORM.md) как `HUMAN_JOURNAL.md` в этот каталог.

Требуемая цепочка демо на настоящем продукте:

3. Находка: 20 000 ₸ нераспределённого платежа, засчитана.

## 3. Найденные проблемы

| № | Где | Проблема в RC3 | Статус |
|---|---|---|---|
| 1 | Список запусков | Таблица шире окна на 1280/1024 px, на 1024 обрезаны кнопки «Расследование» и «Повтор» | Исправлено в ветке: 0 из 24 кнопок обрезано на 1024/1280/1440 |
| 2 | Сравнение пары | Изменённый факт не назван вверху экрана | Исправлено: строки ключ, было → стало; без причинных утверждений |
| 3 | Ошибки | «No open completed run with this id.» по-английски | Исправлено: русские объяснения четырёх кодов API |
| 4 | Чистая компания | F1 = 1.000 при 0/0/0 без пояснения | Исправлено: ссылка на правило SPEC §9 |
| 5 | CLI `list` | Нет компании и роли пары для резервного сценария | Исправлено |
| 6 | HANDOFF | Нет команды для критерия OPS-02 «10 train и 10 dev» | Исправлено: §5а, инструмент `open_sets.py` со строгой сводкой; на образах RC3 `complete`, exit 0 |
| 7 | DEFENSE | Сегмент «расчёт» не помещался в 30 с | Исправлено: 63 слова, 2:16 вместо 2:31 |
| 8 | DEFENSE | Повторные репетиции засоряют список (12 запусков после трёх проходов) | Исправлено: новый каталог для защиты |
| 9 | DEFENSE | Нет короткого резервного сценария с явной пометкой replay | Исправлено: минутный CLI-сценарий |
| 10 | `auditlab.runner` | Docstring говорит `public`, подкоманда `policy` | Открыто: зона runner, отмечено в HANDOFF §5а |

Исправления 1–5 относятся к коду ветки. В опубликованном RC3 их нет, и они попадут к получателю только в
следующем собранном кандидате. Исправления 6–9 — документы. Команда §5а работает на неизменённом RC3.

Проверено отдельно и проблемой не оказалось:
- длинные ID доказательств и таблица расчёта остаются внутри панелей на трёх ширинах (исправление `439aee6`
  в RC3 работает);
- суммы показаны в минимальных единицах и в валюте по `manifest.currency_exponents`;
- клик по ID открывает запись документа;
- ошибки генератора объяснены по-русски с кодом;
- заявлений о конкурсных баллах в интерфейсе нет, награда везде подписана как относящаяся к одной попытке.

## 3а. После ревью интегратора

Исправлены оба контрпримера из [комментария интегратора](https://github.com/Mustiks07/AuditLab/pull/35#issuecomment-7044591495).
Подробности — в [журнале, раздел 8](AGENT_JOURNAL.md).

- **Сводка 10 train + 10 dev больше не скрывает неполноту.** Прежний пример (`submitted` reward 1 и
  `infrastructure_error` без score) теперь даёт `mean_reward null`, измеренную часть 1/2 и exit 1. Вместо двух
  сниппетов один инструмент `auditlab/demo/open_sets.py`; для RC3 его текст встроен в HANDOFF §5а, совпадение
  проверяет тест. На образах RC3 блоки §5а, выполненные буквально, дали 80/80, `complete`, exit 0. С
  отсутствующим образом политики и без Docker-демона — `не проверено`, exit 1.
- **Сравнение произвольных прогонов** больше не утверждает, что различия вызваны датой; текст нейтральный.
- **Второе ревью: допустимость значений.** NaN/Infinity в reward, отрицательные или логические `tp`/`fp`/`fn`,
  нецелый код возврата и некорректные `split`/`episode`/`policy` больше не дают `complete`. Каждый такой случай
  даёт «не проверено», `mean_reward null`, exit 1 и причину, без traceback ([журнал, раздел 9](AGENT_JOURNAL.md)).
  Обычный прогон на образах RC3 по-прежнему `complete`, exit 0.

## 4. Человеческая приёмка

**Не проводилась.** Независимого получателя в этой сессии нет, и агент не может его привлечь. Отдельного
журнала человека нет; агент его не заполнял и не отмечал пункты чек-листа за человека.

Для человека подготовлено:
- [RECEIVER_PACKAGE.md](RECEIVER_PACKAGE.md) — одна страница: ссылка, checksum, требования, порядок действий,
  правила (без подсказок; каждое обращение к авторам записывается);
- [JOURNAL_FORM.md](JOURNAL_FORM.md) — форма журнала со всеми шагами, кодами, временем, затруднениями и
  обращениями за помощью;
- обновлённые [HANDOFF.md](../../demo/HANDOFF.md), [ACCEPTANCE_CHECKLIST.md](../../demo/ACCEPTANCE_CHECKLIST.md)
  и [DEFENSE.md](../../demo/DEFENSE.md).

**Чего не хватает:** владелец проекта находит человека без участия в разработке, с Linux x86_64, Python 3.11 и
Docker (желательно cgroup v2). Передаёт ему только `RECEIVER_PACKAGE.md`. Получает заполненный журнал,
`results/` и снимки экрана и добавляет журнал как `HUMAN_JOURNAL.md` без правок по существу. Если человек
просил помощи, это остаётся в журнале.
