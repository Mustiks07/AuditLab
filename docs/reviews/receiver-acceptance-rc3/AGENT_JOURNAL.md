## 8. Обновление после ревью интегратора (head после `53f47db`)

Интегратор привёл два контрпримера к первой редакции этого PR. Числа разделов 1–6 относятся к исходному RC3 и
не менялись.

**1. Сводка §5а скрывала неполные результаты.** Первый сборщик игнорировал код возврата дочернего процесса, а
сводка считала отсутствующие score/reward нулями. Две строки одной политики — `submitted` с reward = 1 и
`infrastructure_error` без score — давали exit 0 и `mean_reward: 0.5`.

Теперь один инструмент [`auditlab/demo/open_sets.py`](../../../auditlab/demo/open_sets.py) на стандартной
библиотеке:
- `run` записывает для каждой попытки код возврата, разобранный ответ или ошибку разбора и хвост stderr;
- `summarize` принимает только полные 2 × 10 × 4 уникальных ожидаемых попытки с кодом 0, статусом
  `submitted`, score и reward;
- иначе `mean_reward`/`micro` равны `null`, измеренная часть идёт отдельно с знаменателем, код 1 (ошибка)
  или 2 (пропуски).

Для неизменённого RC3 текст инструмента встроен в HANDOFF §5а. Тест проверяет его побайтное совпадение с
файлом. В следующих комплектах файл берётся из `source.tar.gz`.

| Проверка | Результат |
|---|---|
| Контрпример интегратора через CLI `summarize` | `НЕ ПРОВЕРЕНО: mean_reward null; измерено 1/2: TP/FP/FN 1/0/0, среднее по измеренным 1.0`, exit 1 |
| Блоки HANDOFF §5а, выполненные буквально на образах RC3 (classic) | 80 строк, все коды 0, ошибок разбора 0; `status: complete`, exit 0 у `run` и `summarize`, 90 с; [open-sets-rc3-classic.json](open-sets-rc3-classic.json) |
| Тот же запуск с несуществующим образом политики | `run` exit 1; у random/reconcile/flag_all по 10 ошибок с кодом 2 и текстом runner `local policy image is unavailable`; `summarize` exit 1, средние `null` |
| Тот же запуск при остановленном Docker-демоне (случайно, до перезапуска демона) | пустой файл: `файл результатов пуст`, все средние `null`, exit 1 |
| Модульные тесты | упавший процесс с валидной JSON-строкой, отсутствие score и reward, пустой файл, пропущенная строка, пропуск целой компании, повторная строка, неожиданная и неразобранная строка, контрпример интегратора, CLI, совпадение с HANDOFF |

Инструмент и его прогон — код этой ветки, запущенный на неизменённых образах RC3. Опубликованному архиву эти
результаты не приписываются.

**2. Причинная фраза в сравнении.** Фраза «остальные различия — следствия этой даты» показывалась для любого
сравнения без `change_request`, хотя `service.compare` принимает два произвольных прогона. Заменена на
нейтральное «полный список различий — ниже».

## 9. Второе ревью интегратора (head `c34a05c`): проверка входных значений

Сборщик проверял тип значений, но не их допустимость, а ключи использовал до проверки типов. Пример
интегратора (reward = NaN в одной из 80 строк) давал `complete`, exit 0 и `mean_reward: nan`. reward = Infinity
(JSON `1e309`) и `tp = -10` проходили так же. `episode = None` или `[]` приводили к исключению вместо отчёта.

Теперь попытка считается измеренной, только если:
- код возврата — целое 0 (не bool);
- reward — конечный int/float (не bool) в диапазоне [−1, 1] по SPEC §9;
- `tp`/`fp`/`fn` — неотрицательные целые (не bool).

Строка с ключом принимается, только если это JSON-объект с непустыми строками `split`, `episode`, `policy`.
Иначе это некорректная строка с понятной причиной, без traceback. Недопустимая попытка исключается из
измеренных, у затронутой политики `mean_reward`/`micro` = `null`, exit 1.

| Проверка | Результат |
|---|---|
| Воспроизведение интегратора (NaN) | `не проверено`, exit 1, `mean_reward` = None |
| reward `1e309`, `tp = -10` | `не проверено`, exit 1; «reward не конечное число: inf», «score.tp отрицательное: -10» |
| `episode = None`, `episode = []` | `не проверено`, exit 1, «строка 1: нужен JSON-объект с непустыми строками split, episode, policy» |
| Обычные 80 строк | `complete`, exit 0 |
| Обновлённые блоки HANDOFF §5а на образах RC3 (classic) | 80/80, `complete`, exit 0, 79 с; встроенная копия совпадает с файлом |
| Регрессии `InputValues` | NaN, Infinity из JSON, отрицательные и логические/дробные tp/fp/fn, логический/строковый и вне диапазона reward, код возврата False/True/"0"/None/0.0, некорректные ключи, строка-не-объект, CLI |

Это проверка входных значений нового сборщика, а не финансовая ошибка RC3.
