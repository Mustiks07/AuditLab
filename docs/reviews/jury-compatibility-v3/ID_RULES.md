# Правила допустимого преобразования ID и порядка

Выписаны **до** написания проверяющего инструмента. Источники и их версии:

- **[G]** — [определения проверок FinTech](https://genesis-exe.com/fintech-checks.html), опубликованы 20.11.2026.
  Текстовая копия `https://genesis-exe.com/docs/fintech-checks.txt` загружена 22.11.2026, HTTP 200,
  SHA-256 `2a597ebfb94daec700ba9b1b09d62c032366e788c6e992486d444e063be8d870`. Хеш совпадает с прочтением
  21.11.2026, раздел «Изменения» пуст.
- **[S]** — `docs/SPEC.md`, редакция 1.2: §5 «Ссылки», §11 «Безвредное преобразование».
- **[A]** — `docs/GENESIS_ADAPTER.md` (адаптер `judge_adapter.py`).

Статус правила: **обязательно** — прямо сказано в источнике; **разрешено** — источник это допускает;
**не определено** — источник молчит. В последнем случае обязательное требование не придумывается.

## Что источники определяют

| № | Правило | Источник | Статус |
|---|---|---|---|
| R1 | Преобразование делает жюри на копии эпизода; исходник не перезаписывается; агент не видит truth и provenance | G | обязательно (жюри) |
| R2 | Согласованно заменяются идентификаторы и **все ссылки на них**: `row_id`, `doc_id`, `invoice_id`, `payment_id`, `entity_id`, `affected_ids`, `evidence_ids` | G | обязательно |
| R3 | Связи, `null` и суммы сохраняются; разные пространства ID не смешиваются, одинаковые значения в разных таблицах не создают ложной связи | G | обязательно |
| R4 | Записи таблиц и потоков документов можно переставлять; смысловой порядок внутри документа (`line_items`) — нельзя, если схема этого не разрешает | G | разрешено / обязательно |
| R5 | Ключ FX `date:source:target` не суррогатный ID: дату и валютную пару под видом переименования менять нельзя | G | обязательно |
| R6 | Matcher сравнивает ID как точные строки: с учётом регистра и пробелов, без перевода числа в строку, без удаления префиксов, без поиска похожих ID | G | обязательно (команда) |
| R7 | Пары P01–P05 — только перестановка; P06–P10 — только переименование; P11–P20 — оба вместе | G | обязательно (жюри) |
| R8 | Условия прохождения пары: повтор исходника воспроизводит записи, переходы и награды. Оракул на копии сдаёт верные выводы с новыми ID, и после обратного отображения совпадают тип, записи, суммы, валюты и доказательства. TP/FP/FN/P/R/F1 и награда совпадают при одинаковых `inspection_steps`. Нет нового канала утечки и недоступных доказательств. Траектория политики не обязана быть инвариантной | G | обязательно |
| R9 | Взаимно однозначная карта публичных ID; переписать все ссылки, доказательства и эталон; заново построить пагинацию; сравнить после обратного отображения | S §11 | обязательно (команда) |
| R10 | Доказательства — единые публичные ключи `ledger/R72`, `payments/D9`, `invoices/D4`, `fx/2026-11-15/USD/KZT`, `policy/fx_date`; затронутые сущности — `payment/P9`, `invoice/I4`; справочник объясняет перевод сырого ID в публичную ссылку | S §5, A | обязательно (команда) |
| R11 | `payments.settlement_index.unapplied_row_ids` — публичное расширение: перечень строк `ledger` по нераспределённому остатку | S §5, A | обязательно (команда) |
| R12 | `reset` с `episode_dir` загружает каталог как есть. Порядок `list_records` задаётся ключом, а не порядком строк файла. Пример преобразования — `auditlab/release/transforms.py` | A | обязательно (команда) |

## Чего источники не определяют

| № | Вопрос | Почему не определено | Как поступает проверка |
|---|---|---|---|
| U1 | Должен ли внешний преобразователь знать вложенные расширения (`settlement_index.unapplied_row_ids`, `allocation_instructions`) и `journal_id` | G перечисляет пять полей, но требует менять «все ссылки». Список вложенных полей AuditLab на странице не повторяется | Оба варианта — отдельные профили: `discover` по значениям и `literal` по списку полей. Последствия показаны, ни один не объявлен «ошибкой жюри» |
| U2 | `affected_ids` / `evidence_ids` — сырые ID или составные ключи `kind/id` | Примеры G используют `R1`, `D1`, `D2` без префиксов; R6 запрещает удалять префиксы, то есть допускает их | Профили `composite` (часть после `/`) и `opaque` (строка целиком) |
| U3 | Переименовывается ли `journal_id` и `episode_id` | В списке R2 их нет | Не переименовываются; форма групп `journal_id` сравнивается |
| U4 | Может ли новый ID содержать `/`, пробелы или быть числом | Не сказано | Числовые строки проверены (`discover-numeric`). `/` и пробелы не проверялись и требованием не считаются |
| U5 | Порядок внутри `invoice_refs` и `unapplied_row_ids` | Это не «таблицы и потоки документов» и не `line_items` | Сохраняется как есть |

## Что из этого следует для AuditLab

Формат с префиксами допустим (R6, R10) и **не считается ошибочным**. Риск возникает только при
сочетании неопределённостей U1 и U2 с конкретной реализацией преобразователя жюри. Измерения и
минимальные примеры — в [README.md](README.md), раздел 1.
