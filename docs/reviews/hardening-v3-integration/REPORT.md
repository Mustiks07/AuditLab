## Совместимость требований

- **Секретность и повтор.** В профиле 1.3 закрытый эпизод воспроизводится с той
  же доверенной парой seed и настройки с ключом. Ключ должен быть выбран случайно
  и храниться только у доверенной стороны. Сам профиль без ключа не добавляет
  секретности. `private/provenance.json` — материал закрытого повтора, не журнал
  приложения и не вход политики. Организатор может записать входы в собственном
  закрытом журнале. Интеграция убирает seed из событий адаптера и закрытой
  квитанции раннера, а отпечаток ключа заменяет простым маркером редактирования.
- **Новый default и старые рецепты.** Переход относится только к адаптеру и
  отсутствующему `config_version`. Старые `datasets/open` и рецепты остаются
  историческими. Неявный вызов с `documents_target: 201` совместим со старым
  профилем 1.0, но выходит за диапазон 1.3. Для таких рецептов требуется явная
  версия. Проверено на seed `783104`: `company_size={"documents_target":201}`
  даёт 201 документ с `config_version="1.0"`, без версии возвращает
  `invalid_company_size`. Аргументы нового default соответствуют диапазону обычных эпизодов.
- **Составные ссылки и ID.** Смена ID должна охватывать все внешние ссылки,
  включая `settlement_index.unapplied_row_ids` и вложенные ссылки назначения.
  Если меняется `journal_id`, группировка сохраняется. Дата и пара валют FX остаются значениями
  документа. Переименование только верхнеуровневых полей оставляет старые
  ссылки внутри индекса. Независимый `check_links` обнаруживает такой случай.
  [Карта полей и неопределённости](../jury-compatibility-v3/ID_RULES.md)
- **Парный эксперимент и seed.** В 1.3 материал случайности привязан ко всей
  конфигурации. Смена `issue_counts` при том же seed может сменить исходную
  историю. У официальных пар другой контракт: одно создание исходника и
  внешнее преобразование копии. Для внутренних финансовых пар переключатель
  ошибки сохраняет знакомое поведение в 1.2. Для 1.3 нужен отдельный протокол
  парных входов или преобразование согласованной исходной книги.

### Один пример смены исходной истории

У уже зафиксированной пары `9330001` из `plan_b` заданы KZT/USD,
`Asia/Almaty`, ноябрь 2026, цель 200 проводок и 40 документов. Платёж
3 461 841 минорных единиц, доля 5596 базисных пунктов, три транша.
Меняется только `issue_counts.payment_allocation` с 1 на 0.
Число документов 55/55 в 1.2, 55/57 в 1.3. Канонический отпечаток
исходной книги совпал в 1.2, в 1.3 различается.

Запуск из корня репозитория:

```sh
python - <<'PY'
from pathlib import Path
from tempfile import TemporaryDirectory
from datasets.audit_families import fingerprints
from judge_adapter import generate_episode
from review.data_shortcuts.datasets import plan_b

with TemporaryDirectory() as tmp:
    root = Path(tmp)
    rows = [row for row in plan_b(root / "plan", 8) if row["seed"] == 9330001]
    for version in ("1.2", "1.3"):
        families = []
        for row in rows:
            episode = root / version / row["variant"]
            generate_episode(row["seed"], {**row["config"], "config_version": version}, str(episode))
            families.append(fingerprints(episode / "private/source_book")["family"])
        print(version, len(set(families)) == 1)
PY
```
