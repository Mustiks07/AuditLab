## Совместимость требований

- **Секретность и повтор.** В профиле 1.3 закрытый эпизод воспроизводится с той
  же доверенной парой seed и настройки с ключом. Ключ должен быть выбран случайно
  и храниться только у доверенной стороны. Сам профиль без ключа не добавляет
  секретности. `private/provenance.json` — материал закрытого повтора, не журнал
  приложения и не вход политики. Организатор может записать входы в собственном
  закрытом журнале. Интеграция убирает seed из событий адаптера и закрытой
  квитанции раннера, а отпечаток ключа заменяет простым маркером редактирования.
- **Новый default и старые рецепты.** Переход относится только к адаптеру и
  отсутствующему `config_version`. Старые `datasets/open` и рецепты остаются
  историческими. Неявный вызов с `documents_target: 201` совместим со старым
  профилем 1.0, но выходит за диапазон 1.3. Для таких рецептов требуется явная
  версия. Аргументы нового default соответствуют диапазону обычных эпизодов.
- **Составные ссылки и ID.** Смена ID должна охватывать все внешние ссылки,
  включая `settlement_index.unapplied_row_ids`, `journal_id` и вложенные ссылки
  назначения, если они присутствуют. Дата и пара валют FX остаются значениями
  документа. Переименование только верхнеуровневых полей оставляет старые
  ссылки внутри индекса. Независимый `check_links` обнаруживает такой случай.
  [Карта полей и неопределённости](../jury-compatibility-v3/ID_RULES.md)
- **Парный эксперимент и seed.** В 1.3 материал случайности привязан ко всей
  конфигурации. Смена `issue_counts` при том же seed может сменить исходную
  историю. У официальных пар другой контракт: одно создание исходника и
  внешнее преобразование копии. Для внутренних финансовых пар переключатель
  ошибки сохраняет знакомое поведение в 1.2. Для 1.3 нужен отдельный протокол
  парных входов или преобразование согласованной исходной книги.

До новой квитанции отсутствующий замер имеет статус **не проверено**. Ни один
внутренний результат не пересчитывается в конкурсный балл.

## Команды общего прогона

Установить зафиксированные зависимости `python -m pip install --require-hashes -r requirements.lock`.
Использовать новый каталог вывода и точный checkout. Команды поддерживаются
существующими инструментами и workflow `Integration checks`.

```sh
git diff --exit-code d745376 -- datasets/open datasets/recipe.json datasets/build.py
python -m unittest discover -s tests/data_shortcuts -v
python -m unittest discover -s tests/jury_compatibility_v3 -t . -v
python -m unittest discover -s tests/simulator -p test_profile_13.py -v
python docs/reviews/generator-hardening-v3/verify_open_set.py --work artifacts/hardening/finance --out artifacts/hardening/finance.json
python review/genesis_acceptance/run.py --output artifacts/hardening/genesis
python -m review.jury_compatibility_v3.check_ids --generate --output artifacts/hardening/ids-legacy
python -m review.jury_compatibility_v3.check_ids --episodes datasets/open-1.3 --output artifacts/hardening/ids-modern
python -m review.jury_compatibility_v3.gate --genesis artifacts/hardening/genesis/report.json --ids artifacts/hardening/ids-modern/id-transform.json --expected-commit "$(git rev-parse HEAD)" --expected-episodes 20
npm --prefix web ci
npm --prefix web test
npm --prefix web run build
```
