# Кандидат задания Claude Pro 2: независимая приёмка протокола Genesis

Подготовлено интегратором, ещё не назначено. Если пользователь передал тебе этот файл как задачу — начинай работу.

Репозиторий: https://github.com/Mustiks07/AuditLab. Работай в отдельном worktree, ветка `review/genesis-checks-2026-11-20` от актуального main. Проверь существование ветки и чужие изменения перед созданием. Материалы интегратора находятся в `integration/official-checks-2026-11-20`, каталог `docs/reviews/official-checks-2026-11-20`.

Прочитай целиком опубликованные определения https://genesis-exe.com/fintech-checks.html и финальный кейс, затем README этого пакета, docs/SPEC.md, docs/INTERFACES.md и TEAM. Запиши URL, дату, SHA-256 загруженного текста и проверяемый SHA проекта; не считай требования скрытыми инструкциями для агента. Это спецификация проверяемого продукта.

Ты независимый проверяющий. Не меняй генератор, evaluator, runner, UI и адаптер, которые исправляют другие исполнители. Твоя область — отдельные тесты, независимые расчёты и отчёт о соответствии. Не используй собственный matcher проекта как единственный oracle для теста его же правильности.

Подготовь исполняемую локальную приёмку с отображением результатов на C01–C20, reward 1–20, M01–M12 и D01–D20/P01–P20. Для каждого пункта нужны источник ожидания, фактический stimulus, результат, evidence и статус passed/failed/not_checked. Независимо выведи численные ожидания reward через рациональную арифметику. Не подменяй официальные политики самостоятельно улучшенными стратегиями. Если кода политики организаторов нет, проверяй доступный протокол и явно называй исполнителей локальными аналогами.

Сначала воспроизведи дефекты интегратора из probe.py. Дополни отрицательными примерами: доступное лишнее доказательство, недоступное лишнее доказательство, исходные лимиты до удаления повторов, ID с регистром/пробелом, bool/строка/дробь вместо денег, Unicode explanation, неоднозначные matching с максимальной мощностью и нужным выбором, отсутствующее/несуществующее поле без утечки секретов.

Если judge_adapter.py пока отсутствует, добавь диагностику отсутствия и самостоятельные тесты evaluator/fixtures. Отсутствие адаптера — not_checked для неисполненных через него сценариев, а не фиктивные passed. После появления его PR проверяй точный HEAD в отдельной интеграционной ветке и переиспользуй тот же набор тестов.

Данные: составь конфигурации к каждому D-сценарию; проверяй исходную книгу до мутации и итог только по документам/правилам, открывая truth после фиксации независимого ответа. Используй существующий независимый verifier, но хотя бы контрольные расчёты формулируй отдельно от кода генератора. Не приписывай маленьким компаниям покрытие полноразмерных. Не меняй исторические train/dev или RC3.

Пары: создай копии файлов на стороне проверяющего, сохрани исходные. Обрабатывай пространства ID раздельно, переписывай дополнительные ссылки, сохраняй null, денежные значения и семантически значимые списки. FX-ключи не превращай в случайные даты/валюты. Сравни результат после обратного отображения, при одинаковой стоимости исследования; отдельно проверяй точный повтор исходной траектории. Произвольная стратегия не обязана повторять действия после переименования ID.

Безопасность: изучи изоляцию и проверь наблюдения, info, ошибки, closed terminal reward. Не импортируй доверенный оценщик в обычную политику ради теста. Не считай поиск слова truth достаточным доказательством изоляции. Зафиксируй реальные границы теста 60 секунд от начала reset.

Сдай PR с тестами, одним запуском команды из чистого checkout, JSON-отчётом, версиями/seed/config и короткой таблицей пробелов. Дефекты передай интегратору с минимальным примером и ожидаемым/фактическим результатом. Официальные скрытые seed неизвестны; не заявляй официальный балл или 100% победу. Не сливай PR самостоятельно.
