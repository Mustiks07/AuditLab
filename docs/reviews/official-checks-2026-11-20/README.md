Дата: 20.11.2026. Исследованный main: `6f4f7e0cdf6b03d824c835112ee8c010ea9231e1`.

Источники:

- Переданное пользователем `Genesis_Hackathon_Положение_2026.pdf`, все 5 страниц прочитаны. Контрольные суммы исходных документов — в `sources.json`.

Страница определяет транспорт подключения жюри и конкретные проверки. Внутренние результаты AuditLab нельзя автоматически считать результатами этой приёмки. Число баллов и процент готовности по официальным тестам пока не измерены.

## Подтверждённые расхождения

1. **Нет точки входа жюри.** В репозитории отсутствует `judge_adapter.py`. `AuditEnvironment` принимает внутренний `action`, `snapshot_dir` и иначе устроенный submit. При прямой передаче официального envelope возвращает malformed_action. Это отсутствие адаптера, а не доказательство поломки внутренних инструментов. Нужна тонкая обёртка, не новая стратегия аудитора.
2. **Несуществующее дополнительное доказательство не отклоняется.** К правильному oracle-ответу S02 добавлена ссылка `payments/DOES_NOT_EXIST`. `evaluate` всё равно вернул TP=1, FP=0, FN=0, reward=0.98. `_covers` проверяет включение минимального набора, но не доступность всех переданных ссылок. `evaluator.service.handle` передаёт только truth и не исправляет проблему. Требуется доверенная проверка каждого evidence key через публичный индекс данного эпизода. Одного списка ссылок truth недостаточно: допустимое дополнительное доказательство может не входить ни в один минимальный набор.
3. **Неизвестный строковый type считается структурной ошибкой.** Тот же правильный S02 с неизвестной строкой type получил invalid_submission/bad_type. Новая граница между структурой и семантикой требует изменить этот случай. Нестрочные значения остаются невалидными; новые типы генератора из этого не следуют.
4. **Порядок выбора максимального matching отличается.** `_max_matching([[0,1],[0,1]], 2)` возвращает владельцев A/B `[1,0]`. В M11 требуется противоположный выбор `[0,1]`. Это проверка непосредственно алгоритма; она НЕ означает, что текущий validate_truth позволяет собрать такой неоднозначный граф из обычного валидного снимка. Его запрет одинаковых type+affected также нужно согласовать с официальными неоднозначными фикстурами. Простого детерминизма Kuhn недостаточно для требуемого tie-break.
5. **Невалидный submit имеет другой внешний формат метрик.** Внутренний evaluator выдаёт числовые TP/FP/FN при invalid_submission. Адаптер должен вернуть установленный жюри результат с null-метриками и полем `return`, сохранив подробную причину на доверенной стороне. Нельзя ломать внутренние отчёты молчаливой заменой их схемы.

Результаты первых четырёх диагностик воспроизводятся `python docs/reviews/official-checks-2026-11-20/probe.py`; сохранённый вывод — `probe-results.json`. Скрипт ничего не меняет в эпизодах и не обращается к сети.

## Дополнительно требует проверки

- `AuditEnvironment.reset` начинает отсчёт после подготовки снимка/загрузки данных; новый внешний срок начинается раньше. Проверить срок от входа reset, включение времени политики и согласованность с внешним watchdog. Сам факт расположения таймера ещё не является измеренным провалом 60-секундного теста.
- Существующий `rehearsal.selection_manifest` строит свой внутренний набор; `run_pair` применяет совместное преобразование. Это не доказывает прохождение новых распределений D01–D20/P01–P20. Добавить отдельный протокол, не переписывать исторические измерения RC3.
- Проверить загрузку произвольно преобразованного каталога в reset, отсутствие регенерации/переименования и переноса состояния, доступность всех ссылок и сохранение семантического порядка.
- C01–C20, двадцать reward-векторов, M01–M12 и отдельная матрица D/P пока не выполнены в полном объёме через официальный интерфейс. Не обозначать их зелёными по наличию похожих внутренних тестов.
- Политика должна остаться в существующей изоляции, не импортировать score/generate и не получить путь к private. Адаптер запускается на доверенной стороне; одно сокрытие полей класса не решает изоляцию.
