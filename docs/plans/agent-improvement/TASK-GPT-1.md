# Промпт GPT Pro 1: адаптивные задачи и учебные наборы

Ты отвечаешь за генератор AuditLab и поиск слабостей ИИ-аудитора. Дизайн уже принят.
Начни отдельный worktree от актуального origin/main,
ветка `feature/adaptive-financial-curriculum`. Прочитай SPEC целиком, INTERFACES,
TEAM и README/CONTRACTS этого пакета. Не меняй официальный matcher и UI.

Сначала отдельным PR из `feature/full-allocation-omission` закрой Issue #40.
Основной поток начинай параллельно в указанной ветке, затем включи принятый #40
через обновление main. Не жди завершения всех других ролей для начала реализации.

Сделай весь поток поиска, сокращения и подготовки обучения:

1. Проверь существующие paired controls и minimizer, расширь их без дублирования.
   Закрой полный пропуск распределения отдельно от частичного, если он ещё не закрыт:
   согласованная исходная книга, полная сумма не зачтена, независимая проверяемость.
2. Построй поиск по поддерживаемым параметрам финансовых семей. Начни с прозрачного
   стратифицированного поиска и адаптации по частоте ошибок/неопределённости. Сравни
   с равномерным поиском при одинаковом бюджете; не называй метод PAIRED без его реализации.
3. Каждый кандидат проходит независимый финансовый валидатор и проверку возможности
   получить необходимые доказательства в бюджете. Трудность не создаётся сокрытием данных.
4. Для обнаруженного провала сохрани повторы агента, затем сократи пример с сохранением
   бухгалтерских инвариантов, ссылок и измеряемой частоты сбоя. Старый ответ на новом
   эпизоде не заменяет повторного расследования. Отдельно укажи, что сокращено и что нет.
5. Реализуй семейства преобразований: оформление; чистые отвлекающие операции;
   исправление дефекта; существенное изменение финансового основания. Все производные
   входят в то же разбиение, что родитель. Подтверди ожидаемые изменения ответа.
6. Выдай версионный curriculum с происхождением примеров, бюджетом отбора, дедупликацией
   по экономической структуре и экспортом для Claude 1. Truth/учительские ответы доступны
   только на стадии подготовки train; в наблюдения агента и финальный тест не попадают.

Приёмка: реальный агент, а не только mock, использован в полном цикле поиска и
сокращения; независимый validator принял примеры; чистые аналоги не содержат дефектов;
сравнение поиска имеет одинаковый бюджет; train/dev/test не пересекаются семействами.
Нельзя гарантировать, что любая модель даст устойчивый провал: отсутствие найденных
ошибок тоже сохраняется вместе с объёмом поиска. Приложи PR, SHA, команды, артефакты,
фактические измерения и непроверенные пункты. Не сливай main самостоятельно.
