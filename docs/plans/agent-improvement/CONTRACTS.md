## Предлагаемые артефакты

Во всех JSON: `schema_version`, `artifact_id`, `source_sha`, `protocol_id`.
Числа конечные; счётчики целые неотрицательные; отсутствие результата — null и причина,
не ноль. Хеши содержимого фиксируются после записи; приватные данные не публикуются
в UI/API по умолчанию. Идентификаторы не заменяются человеческими именами в протоколе.

| Артефакт | Обязательные сведения |
|---|---|
| experiment.json | Разбиение и его хеш, модели/параметры/промпты, варианты, повторы, бюджеты, лимиты времени, правила анализа |
| candidate.json | Генератор/профиль/config/seed на доверенной стороне, family_id, split, parent, мутация, хеши snapshot, история поиска |
| validation.json | Проверка исходной книги, независимый расчёт, совпадение truth, доступность доказательств, допустимая по бюджету траектория свидетеля, причины отказа |
| attempt.json | agent/model/prompt hashes, episode hash, repetition, timestamps, действия и наблюдения, финальный ответ, статус, токены/стоимость/время, ссылки на закрытую оценку |
| failure.json | Проверяемый критерий ошибки, все исходные и повторные попытки, частота и неопределённость, альтернативные объяснения |
| reduction.json | Исходный и сокращённый snapshots, преобразования, независимая валидация и повторные попытки до/после |
| curriculum.json | Семейства/разбиение, происхождение и фильтрация примеров, хеши, поддерживаемый формат экспорта обучения |
| training.json | Исходная модель, данные, настройки, бюджет/факт, job/checkpoint identity, результат/ошибка; отдельно kind=weights/prompt/few_shot |
| comparison.json | Полная выборка, варианты, метрики и знаменатели, парные интервалы, пропуски, затраты и ссылки на исходные попытки |

Итоговые статусы проверки: `passed`, `failed`, `not_checked`. Операционные статусы
попыток отделены: завершена, timeout, ошибка провайдера, некорректный ответ, остановка
по бюджету. Не объявлять финансовый результат для попытки, которую нельзя оценить.

## Предлагаемые команды

Общий CLI проектируется интегратором как `python -m auditlab.research ...`:
`validate-plan`, `run`, `search`, `reduce`, `build-curriculum`, `train`, `compare`, `replay`.
Это спецификация будущего CLI; пока команды не реализованы. Все используют версионный
конфиг, manifest и новые каталоги вывода; resume не дублирует оплаченные вызовы или
задания обучения. Нужны dry-run, ограничение расходов и корректное сохранение при сбое.

Агент получает observation, состояние своих заметок и допустимые инструменты;
возвращает только разрешённое действие. Заметки — факты/ссылки/проверяемые гипотезы,
не запрос скрытых цепочек рассуждения модели. Локальный валидатор может проверять
структуру и уже полученные публичные ссылки; он не вычисляет ответ по truth и не
приписывает модели собственное исправление финансового вывода.

Поиск использует только training/search разделы. Сокращатель принимает независимый
валидатор и предикат повторяемого сбоя, не просто наличие старого ошибочного ответа.
UI читает только разрешённую проекцию артефактов, никогда ключ API/приватный каталог.
