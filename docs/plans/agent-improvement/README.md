# Следующая итерация: AuditLab исследует и улучшает финансового ИИ

Статус: пакет готов к выдаче внешним рабочим агентам; это не означает их автоматический запуск.
Обновлено 21.11.2026 после приёмки PR #32, #35–#39. База
`611163e75468f4af95cfa115f033e7a9f8c81145` (465 тестов общего CI).
Работу начинаем от актуального origin/main. Это полный объём
следующей итерации, а не обещание ограничиться подключением модели или одним примером.

Цель: получить работающий цикл «подключили агента → нашли устойчивую ошибку →
независимо подтвердили задачу → сократили пример → сформировали обучение →
проверили изменение качества на новых финансовых историях». Победа — цель команды,
но место и превосходство над неизвестными соперниками нельзя объявлять измеренным результатом.

## Полный объём

1. Сильный агент через API использует только публичное наблюдение и разрешённые
   действия; поддерживаются простой вариант и вариант со структурированными заметками.
2. Генератор ищет области ошибок агента; каждое принятое испытание имеет согласованную
   исходную книгу, корректную мутацию, независимый расчёт и доступные доказательства.
3. Сокращение сохраняет финансовую корректность, разрешимость и измеряемую частоту
   ошибки агента. Если сокращение невозможно, сохраняется исходный пример с причиной.
4. Семейства включают изменение оформления и изменение финансового основания:
   переименование, порядок, законные отвлекающие операции, исправление дефекта,
   существенное изменение оплаты/распределения. Изменения policy — только в явно
   поддерживаемых генератором согласованных сценариях, без смены официальных правил.
5. Учебные данные и эксперименты сравнивают случайные и адаптивно подобранные задачи.
   Реализуется путь реального обучения весов поддерживаемой модели; изменение промпта,
   память и few-shot оцениваются отдельно и не называются обучением весов.
6. Консоль показывает весь цикл по реальным артефактам, включая ошибки, отсутствие
   улучшения и непроведённые проверки. Запись запуска не выдаётся за живой запуск.
7. Один интеграционный запуск связывает SHA, данные, агент, модель, конфигурацию,
   обучение, траектории и оценки. Основной автономный комплект сохраняет офлайн-запуск.

## Порядок и зависимости

Официальный адаптер, evaluator/runner и C3 уже приняты. Новые ветки создаются
от принятого main. #40 выполняется параллельно подготовке остальных компонентов;
генераторный пробел должен быть закрыт до окончательного набора экспериментов. В первый общий контракт
входят форматы из CONTRACTS.md; расширения согласуются через интегратора.
Claude 1 и GPT 1 разрабатывают свои интерфейсы параллельно на явно помеченных
фикстурах; Claude 2 заранее фиксирует независимый протокол; Claude 3 подключает UI к
схемам, затем к настоящим результатам. Интегратор соединяет все компоненты и
проверяет полный цикл, а не сумму отдельных unit-тестов.

Наличие API-агента не разрешает сеть в обычном sandbox. Сетевой мост живёт отдельно,
имеет только разрешённое публичное наблюдение, ограниченный провайдерский endpoint
и секрет из окружения; у него нет доступа к truth, приватным файлам и хостовой ФС
через инструменты. Сервер эксперимента оценивает ответы только на доверенной стороне.

Официальные 60 секунд включают задержки API, повторы и время политики; лимит действий
не расширяется. Исследовательские запуски с иным лимитом имеют отдельный protocol_id
и не засчитываются как прохождение официальной приёмки. Транспортный сбой, timeout,
ошибка ответа и финансовый FP — разные результаты; неудачные запуски не выкидываются.

## Эксперимент, который нужно подготовить и провести

- До поиска и обучения зафиксировать разбиение по экономическим семействам,
  каноническим структурам и параметрам. Новый seed сам по себе не означает новую историю.
  Чистые и ошибочные варианты одной семьи принадлежат одному разделу.
- Предварительная цель финальной выборки: 100 независимых семейств, в каждом чистый
  и ошибочный варианты; по 3 запуска стохастического агента. Это план, не выполненные
  измерения. Claude 2 закрепляет состав и протокол до доступа разработчиков к ответам.
- Сравнить пустую, массово обвиняющую, простую эвристическую и документальную политики;
  затем одну модель без памяти и с памятью. Не подменять поиск инструментов оракулом.
- Для обучения: одна исходная обучаемая модель, одинаковые настройки и сопоставимый
  бюджет токенов/шагов. Ветви: без обучения, обучение на случайном наборе, обучение на
  подобранном наборе. Отдельно измерить стоимость поиска и получения учебных ответов.
- Провайдер/модель выбираются по фактической доступности API и обучения. Если для
  сильной API-модели нет обучения весов, исследуется отдельно доступная обучаемая модель;
  результаты разных моделей не смешиваются в причинное утверждение об эффекте подбора.
- Финальный тест запускается после фиксации конфигураций; по его результатам не
  подбираются промпты и примеры. Новая доработка требует новой нетронутой выборки.
- Метрики: micro F1, средняя награда, FP на чистых, доля завершений, timeout/ошибки,
  действия, токены, время, денежная стоимость. Публиковать знаменатели и распределения.
  Парные различия и интервалы неопределённости считать по семействам, а не выдавать
  повторные запуски одного эпизода за независимые компании.
- Устойчивость к оформлению и чувствительность к исправлению дефекта — отдельные
  метрики. Не требовать одинаковой траектории модели на переименованных документах.
- Все запуски входят в manifest. Сохранённая траектория позволяет пересчитать оценку,
  но не гарантирует побитово одинаковый новый ответ сервиса модели.

## Ресурсы и честная приёмка

Сейчас никакие платные API-вызовы, обучение или удалённые задания не запускаются.
Перед запуском фиксируются доступный провайдер, способ безопасной передачи ключа,
model ID, поддержка обучения, лимиты расходов и ресурсов. Ключи в чат не запрашивать.
Не заданный бюджет означает остановку платного исполнения, а не безлимитные расходы.
Подготовку кода, схем, сухого запуска и локальных проверок это не блокирует.

Основная поставка проверяется без сети и в целевых 4 ГБ всей машины. API-эксперименты,
обучение и локальная модель на отдельном GPU имеют явно отдельные ресурсные профили.
Нельзя обещать запуск сильной локальной модели в 4 ГБ до фактического измерения.

Приёмка требует работоспособности всех перечисленных компонентов, одного полного
измеренного эксперимента и независимой перепроверки. Положительный эффект обучения
не является условием честности результата: нулевой или отрицательный эффект публикуется.
Если доступ/ресурсы отсутствуют, пункт остаётся «не проверено» с конкретной причиной,
а итерация не объявляется полностью выполненной. Официальный балл не вычисляется из
внутренних F1. Исторические релизы и свидетельства сохраняются.
