# Чек-лист независимой приёмки комплекта и консоли (OPS-02 / UI-01)

Для человека, который **не участвовал в разработке**. Начните с одностраничного [пакета получателя](../reviews/receiver-acceptance-rc3/RECEIVER_PACKAGE.md);
записывайте результаты в [форму журнала](../reviews/receiver-acceptance-rc3/JOURNAL_FORM.md). Проверка разработчика или AI-агента этот пункт не закрывает.
Идите по [HANDOFF.md](HANDOFF.md) без помощи авторов. Зависимости проекта не устанавливайте, комплект исходным
checkout не подменяйте. Каждое затруднение записывайте дословно: команду, вывод, время.

Опубликованный кандидат — **`v0.1.0-rc.3`**, source
**`b7a1857a51bf47bb36e42699988b38b4d897fa1f`**. Скачивайте только со [страницы RC3](https://github.com/Mustiks07/AuditLab/releases/tag/v0.1.0-rc.3)
архив и файл checksum. `TAG`, имена файлов и команды — в HANDOFF.md.
RC2 и [его агентская проверка](RC2_AGENT_CHECK.md) остаются историческими свидетельствами.
Ни один пункт ниже ещё не отмечен за независимого получателя.

## 0. Окружение

- [ ] `uname -srm`, `/etc/os-release`, `python3.11 --version`, `docker --host unix:///var/run/docker.sock version`.
- [ ] `docker --host unix:///var/run/docker.sock info --format '{{.Driver}} {{.DriverStatus}} cgroup={{.CgroupVersion}}'` — запишите хранилище
  (`overlay2` или `io.containerd.snapshotter.v1`) и версию cgroup. На v1 лимиты не подтверждаются, коды 2 законны.
- [ ] До загрузки сохранить `docker --host unix:///var/run/docker.sock image ls --no-trunc`.
  Сопоставить три роли с ID/тегами из `manifest.json`: на чистом проверочном хосте этих образов ещё нет.
  Отсутствие образов проекта не означает, что надо удалять чужие образы или контейнеры.

## 1. Комплект

- [ ] `test -f "$ZIP" && sha256sum -c "$SUMS" --ignore-missing` → именно `AuditLab-v0.1.0-rc.3-offline.zip: OK`, exit 0. Записать фактическую SHA-256 ZIP.
- [ ] Распаковка в **новый пустой** каталог: шесть файлов в корне.
- [ ] `python3.11 offline.py check` → `Bundle hashes verified; source b7a1857a51bf47bb36e42699988b38b4d897fa1f`, exit 0. Source в `manifest.json` совпадает.
- [ ] `python3.11 offline.py verify --suite quick --output-root ./results` → **347 тестов без пропусков**, 8 наборов.
  Exit **0** при подтверждённых фактических лимитах контроллера; **2**, если ресурсы не подтверждены.
  Код 0 быстрого прогона не означает полную приёмку. Записать длительность, три `loaded_images` и совпадение `launch.json.source_revision` с manifest.
- [ ] `python3.11 offline.py verify --suite rehearsal --output-root ./results` → 20/80/20, строгий exit **2**.
  В отчёте проверить конкретные открытые пункты OPS-01 / OPS-02; другие ошибки не списывать на ожидаемый код.
  Для каждой политики `planned = measured = 20`, `failed = not_checked = 0`, `score_status = complete`.
  Фактические TP/FP/FN и средние сверить с evidence RC3 того же SHA, не с RC2.
- [ ] Evidence checker (HANDOFF.md, раздел 4): при всех фактических ресурсных свидетельствах —
  `internal_rehearsal_passed`, exit **0**, `failures = missing = []`. Один cgroup v2 без подтверждённых
  контроллеров недостаточен. Недостающие свидетельства — «не проверено», 2; пункт в `failures` — дефект, 1.
- [ ] Суммарный лимит контроллера и одновременно работающего контейнера политики/verifier — 3 GiB. Память всей ОС/daemon отдельно
  **не проверена**; не делать вывод «весь хост уложился в 4 GB» по лимитам контейнеров.
- [ ] `docker --host unix:///var/run/docker.sock events` во время проверки: нет `image pull`, сеть контейнеров проверки только `none`.
- [ ] Прерывание после старта контейнеров: Ctrl+C или SIGINT только launcher → **130**;
  отдельный запуск с SIGTERM только launcher → **143**. `launch.json` содержит `interrupted`, номер
  сигнала, `cleanup.status = passed`, `remaining_containers = 0`. Сохранить оба каталога.
- [ ] Команда с фильтром `label=org.auditlab.launch=<launch_id>` из HANDOFF.md не находит контейнеров
  этого запуска; другие контейнеры остаются. Повторный `verify` создаёт новый каталог и проходит заново.
- [ ] Обязательные политики на 10 train и 10 dev (HANDOFF §5а): 80 строк, у каждой `submitted`; таблица
  TP/FP/FN по наборам и политикам записана в журнал.
- [ ] (Если доступна вторая машина или демон) то же на другом хранилище Docker.

## 2. Консоль (3–5 минут, по [DEFENSE.md](DEFENSE.md))

- [ ] Демо стартует командой из HANDOFF.md; `http://127.0.0.1:8765/` открывается. В инструментах разработчика
  браузера (Network) нет запросов к другим хостам.
- [ ] На списке плашка «демонстрация, а не измерение». Понятно ли, где измеренные результаты?
- [ ] Пара `train-boundary` → «Сравнить пару (B − A)»: две сгенерированные компании, Δ = 20 000,00 ₸.
- [ ] Расследование B → `ledger/RB74667B…` → `public/ledger.csv · строка 76`, поле `debit_minor` подсвечено.
- [ ] При ширине окна 1440 и 1024 px длинные ID, файл/строка и шаг получения доказательства остаются
  внутри карточки. Таблица расчёта на узкой панели прокручивается горизонтально, в том числе стрелками
  после фокуса; клик по полному ID открывает запись документа.
- [ ] Сумма 20 000,00 ₸ раскрывается в 5 000 000 − 3 000 000 мин. ед.; строки «Оценщик», «Консоль», «SQL»
  согласны. У дубля счёта 12 000,00 ₸ показана SQL-арифметика.
- [ ] Изменение факта у A: `ledger/R1356C5BA3E13DFDB078B6E60` → `2026-12-01T00:01:00+05:00` → новый прогон с
  отметкой «настоящий генератор… до границы → после границы»; исходный прогон остался в списке.
- [ ] Неверная дата (например `2026-12-03T00:00:00+05:00`) → понятное русское объяснение с кодом
  `generator_unsupported` и списком допустимых дат.
- [ ] Копия сдачи нового прогона без зачёта `ledger/RB74667B…`: TP 2 → 1, «больше не подтверждено … 30 000,00 ₸».
- [ ] «Повтор опыта»: метка «ПОВТОР ЗАПИСИ»; «Повторить действия и оценку» → «ЖИВОЙ ПЕРЕСЧЁТ · выполнен сейчас …»,
  наблюдения и оценка совпали.
- [ ] Чистая компания `E04F4ED6…`: «Ошибок не заявлено», TP/FP/FN 0/0/0, SQL — 0 расхождений.
- [ ] Резерв без браузера: `crosscheck --live` в контейнере `--network none` проверяет **непустой** набор,
  код 0, наблюдения и реально пересчитанная оценка совпали. `replay --check` реального `run_id` → «совпали».
  Пустой набор и недоступный эталон не считаются успехом.

## 3. Что сдать

Журнал прохождения: SHA, image ID, хранилище, версии, команды, коды возврата, длительности. Снимки экрана
пунктов раздела 2. Список затруднений инструкции с цитатами и подтверждение отсутствия скрытых установок и
загрузок. Формулировка вывода: «независимая человеческая проверка комплекта … на машине …», без утверждений
о конкурсных баллах.
