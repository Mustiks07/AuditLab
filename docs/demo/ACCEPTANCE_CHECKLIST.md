# Чек-лист независимой приёмки комплекта и консоли (OPS-02 / UI-01)

Для человека, который **не участвовал в разработке**. Проверка разработчика или AI-агента этот пункт не закрывает.
Следуйте [offline.md](../release/offline.md) без помощи авторов. Зависимости проекта не устанавливайте, комплект
исходным checkout не подменяйте. Каждое затруднение записывайте дословно: команду, вывод, время.

**Версия для этой приёмки:** следующий кандидат, включающий изменения PR #17.
Его имя, source SHA и checksum передаёт интегратор вместе с архивом. До публикации
такого кандидата пункты нового интерфейса ниже имеют статус «не проверено».
Не скачивайте RC1 для подтверждения этих исправлений: его кнопки, подписи и порядок пары
отличаются. Фактическая проверка прежнего RC1 сохранена отдельно в [RC1_AGENT_CHECK.md](RC1_AGENT_CHECK.md).

## 0. Запишите окружение

- [ ] ОС и ядро (`uname -srm`, `/etc/os-release`), `python3.11 --version`, `docker version`.
- [ ] `docker info --format '{{.CgroupVersion}} {{.Driver}} {{.DriverStatus}}'`.
  Нужен **cgroup v2**; на v1 лимиты не подтверждаются, и это законно даёт exit 2.
  Хранилище образов должно быть классическим (`Driver` = `overlay2`); если в `DriverStatus` указан
  `io.containerd.snapshotter.v1`, см. раздел «Перед запуском» в offline.md.
- [ ] `docker images -q | wc -l` до загрузки: образов проекта быть не должно.

## 1. Комплект

- [ ] Скачать указанный интегратором `AuditLab-VERSION-offline.zip` и `…-SHA256SUMS.txt`; записать VERSION и SHA, `sha256sum -c … --ignore-missing` → `OK` именно для скачанного ZIP.
- [ ] Распаковать; `python3.11 offline.py check` → `Bundle hashes verified; source <SHA>`, exit 0. Записать SHA.
- [ ] `python3.11 offline.py verify --suite rehearsal --output-root ./results` → строки наборов, затем
  `status=incomplete`, **exit 2**. Это ожидаемо и не скрывается. Записать длительность и три загруженных image ID;
  сравнить с `manifest.json`.
- [ ] Evidence checker из `source.tar.gz` — команда в offline.md. Ожидаемо `internal_rehearsal_passed`, exit 0
  на cgroup v2 с работающими лимитами. Любой пункт в `failures` — дефект, о нём нужно сообщить.
- [ ] Во время запуска нет установок и сетевых загрузок: в отдельном терминале `docker events` — нет `image pull`,
  контейнеры проверки подключаются только к сети `none`.

## 2. Консоль (3–5 минут, по [DEFENSE.md](DEFENSE.md))

- [ ] Демо стартует командой из offline.md; `http://127.0.0.1:8765/` открывается. В инструментах разработчика
  браузера (Network) нет запросов к другим хостам.
- [ ] На списке видна плашка «учебная демонстрация, а не измерение». Понятно ли, где измеренные результаты?
- [ ] «Сравнить пару (B − A)»: A = S01 «Ошибок не заявлено», B = S02 20 000,00 ₸; Δ = 20 000,00 ₸.
- [ ] Расследование S02 → `ledger/R5` открывает `public/ledger.csv · строка 6`, поле `debit_minor` подсвечено.
- [ ] Сумма 20 000,00 ₸ раскрывается в операнды 5 000 000 − 3 000 000 мин. ед.; строки «Оценщик», «Консоль», «SQL» согласны.
- [ ] Изменение факта S01 `ledger/R7` → `2026-12-01T00:01:00+05:00` создаёт новый прогон; исходный остаётся в списке.
- [ ] Копия сдачи нового прогона с `ledger/R5 → ledger/R6`: TP 1 → 0, награда −1, «больше не подтверждено … 30 000,00 ₸».
- [ ] «Повтор опыта» → «Повторить действия и оценку»: наблюдения и оценка совпали.
- [ ] Ошибка операции: FX01 `payments/D9` → `2026-12-05T10:00:00+05:00` даёт понятное русское объяснение с кодом.
- [ ] Резерв без браузера: `replay --check` реального `run_id` в контейнере `--network none` печатает «совпали».

## 3. Что сдать

Журнал прохождения: SHA, image ID, версии, команды, коды возврата, длительности. Снимки экрана пунктов раздела 2.
Список затруднений инструкции с цитатами и подтверждение отсутствия скрытых установок и загрузок.
Формулировка вывода: «независимая человеческая проверка комплекта … на машине …», без утверждений о конкурсных баллах.
