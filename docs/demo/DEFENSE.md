# Сценарий защиты: 3 минуты

Цепочка: **настоящая компания → документы → аудитор, оценщик, независимый расчёт → изменение одного факта →
значение доказательства → повтор и пустой ответ чистой компании**.

Все компании синтетические. Это **демонстрация отдельных прогонов** на открытых данных: награды на экране
объясняют механику оценки одного прогона и не являются конкурсным баллом или средним по набору. Измеренные
результаты внутренней репетиции (20 снимков, 80 попыток, 20 пар, ресурсы) лежат в
`results/verify-…/verify/report.json` и `evidence-summary.json`; их границы описаны в
[VALIDATION.md](../release/VALIDATION.md).

> **Какой комплект нужен.** Сценарий для `v0.1.0-rc.3`, source
> `b7a1857a51bf47bb36e42699988b38b4d897fa1f`: используйте архив после подтверждения публикации
> на [странице RC3](https://github.com/Mustiks07/AuditLab/releases/tag/v0.1.0-rc.3).
> Передача и проверка checksum описаны в [HANDOFF.md](HANDOFF.md).
> RC2 — исторический кандидат: у него только ручная пара S01/S02 и FX01, для него сохранён
> [сокращённый вариант](#вариант-для-v010-rc2) в конце. Его результаты не подтверждают новый архив.

## Подготовка (до выхода к жюри)

**Из офлайн-комплекта**, после `python3.11 offline.py verify` (образы уже загружены; подробно в
[HANDOFF.md](HANDOFF.md)):

```sh
AUDITLAB_RUNTIME_IMAGE=$(python3.11 offline.py image --role runtime)
mkdir -p demo-results
docker --host unix:///var/run/docker.sock run --rm --pull never --user "$(id -u):$(id -g)" --read-only --cap-drop ALL \
  --security-opt no-new-privileges --cpus 2 --memory 2g \
  --tmpfs /tmp:rw,nosuid,size=1g -p 127.0.0.1:8765:8765 \
  --mount "type=bind,src=$(pwd)/demo-results,dst=/results" \
  "$AUDITLAB_RUNTIME_IMAGE" python run.py demo --host 0.0.0.0 --root /results/demo
```

**Для разработчика из checkout (не маршрут независимой приёмки архива):**

```sh
python -m pip install --require-hashes -r requirements.lock
```

```sh
python run.py demo
```

Откройте `http://127.0.0.1:8765/`. Первый старт занимает несколько секунд: настоящий раннер проходит шесть
компаний, после чего `/demo/health` отвечает `"runs":6`. `run_id` назначает раннер, он меняется от запуска к
запуску; ID берите с экрана или командой `list` в контейнере (ниже). ID эпизодов и строк ниже
постоянны: они из опубликованного `datasets/open/train`.

Перед выходом сверьте консоль с экспортами и выполните живой пересчёт. Для получателя архива
команда выполняется в поставленном контейнере, без установки пакетов на хосте. Ожидается шесть
проверенных запусков (или больше после собственных опытов), «расхождений: 0», exit 0:

```sh
docker --host unix:///var/run/docker.sock run --rm --pull never --network none --user "$(id -u):$(id -g)" \
  --read-only --cap-drop ALL --security-opt no-new-privileges --cpus 2 --memory 1536m --memory-swap 1536m \
  --pids-limit 256 --tmpfs /tmp:rw,size=64m \
  --mount "type=bind,src=$(pwd)/demo-results,dst=/results" "$AUDITLAB_RUNTIME_IMAGE" \
  python -m auditlab.demo --root /results/demo crosscheck --live
```

## Если спросят или что-то пойдёт не так

- **Совпадает ли консоль с CLI?** `crosscheck --live` сверяет каждое показанное значение с файлами экспорта и
  выполняет пересчёт. На снимках репетиции RC2 `crosscheck --rehearsal …` повторил 20 из 20 CLI-попыток
  reconcile: выводы, суммы, валюты (KZT, USD, JPY с 0 знаков, KWD с 3), доказательства, TP/FP/FN, награда и
  действия совпали ([RC2_AGENT_CHECK.md](RC2_AGENT_CHECK.md)).
- **Ошибка операции.** Ввести дату `2026-12-03T00:00:00+05:00`: «настоящий генератор меняет в этой компании
  только время последнего зачёта… [generator_unsupported: Генератор ставит этот зачёт только на: …00:00
  (ровно на границе); …00:01 (после границы)]». Новая компания не публикуется.
- **Единицы.** В файлах все суммы — целые минимальные единицы; на экране рядом сумма по разрядности из
  `manifest.currency_exponents` (KZT — 2 знака, JPY — 0, KWD — 3).
- **Браузер недоступен.** Те же данные без сети:

```sh
docker --host unix:///var/run/docker.sock run --rm --pull never --network none --user "$(id -u):$(id -g)" --read-only --cap-drop ALL --tmpfs /tmp:rw,size=64m \

  python -m auditlab.demo --root /results/demo list
```

```sh

  --mount "type=bind,src=$(pwd)/demo-results,dst=/results" "$AUDITLAB_RUNTIME_IMAGE" \
  python -m auditlab.demo --root /results/demo show --run RUN_ID
```


(`show --json` равен ответу API, это проверяет тест).

## Вариант для `v0.1.0-rc.2`

В консоли RC2 три прогона: ручная пара S01/S02 и FX01. Цепочка та же, но на маленькой паре:
«Сравнить пару (B − A)» → Δ 20 000,00 ₸; S02 → `ledger/R5` → `public/ledger.csv · строка 6`;
изменение факта S01 `ledger/R7` → `2026-12-01T00:01:00+05:00` (учебный адаптер, не генератор); копия сдачи
`ledger/R5 → ledger/R6` (TP 1 → 0); «Повторить действия и оценку»; пустой ответ — S01. Живой пересчёт там
работает, но без отметки времени на экране. Все шаги агент проверил на обоих хранилищах Docker
([RC2_AGENT_CHECK.md](RC2_AGENT_CHECK.md)).

## Чего этот сценарий не доказывает

Он не измеряет качество аудитора на неизвестных компаниях и не заменяет закрытые проверки организатора.
В изменении факта генератор меняет только один документированный параметр — время последнего зачёта
относительно границы; произвольные правки документов не поддерживаются. Для ручных примеров действует
учебный адаптер с двумя операциями. Аудитор, раннер, оценщик и сверка во всех случаях настоящие.
