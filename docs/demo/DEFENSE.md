# Сценарий защиты: 3 минуты

Цепочка: **контрольная пара → доказательства → расчёт → изменение факта → изменение оценки → повтор результата**.
Все суммы синтетические. Это **учебная демонстрация** на открытых данных: награды на экране объясняют
механику оценки одного прогона и не являются конкурсным баллом. Измеренные результаты внутренней
репетиции (20 снимков, 80 запусков, 20 пар, ресурсы) — в `results/verify-…/verify/report.json` и
`evidence-summary.json`; их границы описаны в [VALIDATION.md](../release/VALIDATION.md).

## Подготовка (до выхода к жюри)

**Из офлайн-комплекта** (после `python3.11 offline.py verify`, образы уже загружены; команда из
[offline.md](../release/offline.md), сеть контейнеру нужна только для проброса порта на localhost):

```sh
AUDITLAB_RUNTIME_IMAGE=$(python3.11 -c "import json; print(json.load(open('manifest.json'))['images']['runtime']['id'])")
mkdir -p demo-results
docker run --rm --pull never --user "$(id -u):$(id -g)" --read-only --cap-drop ALL \
  --security-opt no-new-privileges --cpus 2 --memory 2g \
  --tmpfs /tmp:rw,nosuid,size=1g -p 127.0.0.1:8765:8765 \
  --mount "type=bind,src=$(pwd)/demo-results,dst=/results" \
  "$AUDITLAB_RUNTIME_IMAGE" python run.py demo --host 0.0.0.0 --root /results/demo
```

**Из checkout разработчика:** `python -m pip install --require-hashes -r requirements.lock`, затем
`python run.py demo`.

Откройте `http://127.0.0.1:8765/` (сервер в контейнере слушает `0.0.0.0`, браузер открывает localhost).
Первый старт строит три учебных прогона, после чего `/demo/health` отвечает `"runs":3`. `run_id` назначает настоящий раннер и меняется от
запуска к запуску: берите ID с экрана или из `python -m auditlab.demo --root … list`, не из этого текста.

## Если спросят или что-то пойдёт не так

- **Ошибка операции (показать по желанию).** FX01 → `payments/D9` → «Изменить факт…» → `2026-12-05T10:00:00+05:00`.
  Ответ: «ошибка запуска: учебный адаптер не поддерживает такое изменение (например, перенос платежа в другой
  отчётный период…) [unsupported_counterfactual: …]». Перенос в другой период требует полного генератора;
  исходная попытка не меняется, новая не публикуется. Неверный формат даты даёт `invalid_value` с примером.
- **Пустой ответ.** Расследование A (S01): «Ошибок не заявлено», консоль и SQL — расхождений 0.
- **Единицы.** В файлах все суммы — целые минимальные единицы (тиын, цент); на экране рядом показана сумма
  по разрядности из `manifest.currency_exponents` (KZT — 2 знака, JPY — 0, KWD — 3).
- **Браузер недоступен.** Те же данные в контейнере без сети:

```sh
docker run --rm --pull never --network none --read-only --cap-drop ALL --tmpfs /tmp:rw,size=64m \
  --mount "type=bind,src=$(pwd)/demo-results,dst=/results" "$AUDITLAB_RUNTIME_IMAGE" \
  python -m auditlab.demo --root /results/demo list
docker run --rm --pull never --network none --read-only --cap-drop ALL --tmpfs /tmp:rw,size=64m \
  --mount "type=bind,src=$(pwd)/demo-results,dst=/results" "$AUDITLAB_RUNTIME_IMAGE" \
  python -m auditlab.demo --root /results/demo show --run RUN_ID
docker run --rm --pull never --network none --read-only --cap-drop ALL --tmpfs /tmp:rw,size=64m \
  --mount "type=bind,src=$(pwd)/demo-results,dst=/results" "$AUDITLAB_RUNTIME_IMAGE" \
  python run.py replay --root /results/demo --run RUN_ID --check
```

`show` печатает те же шаги, ссылки на строки, операнды, вердикт и строку SQL, что и экран
(`show --json` равен ответу API, это проверяет тест).

## Чего этот сценарий не доказывает

Он не измеряет качество аудитора и не заменяет закрытые проверки организатора. Учебная замена
(`generator: demo-standin`) строит изменённую компанию только для двух операций: перенос зачёта и перенос
платежа внутри периода. Аудитор, раннер, оценщик и сверка при этом настоящие.
