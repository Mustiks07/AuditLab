## Соответствие консоли настоящим CLI-результатам

Проверка выполнена **кодом консоли из этого PR** (checkout), а не образом RC2: в RC2 этой команды нет.

| Проверка | Результат |
|---|---|
| `crosscheck --rehearsal RESULTS/verify/rehearsal` на результатах classic | 20 из 20 снимков совпали с CLI-попытками reconcile (`final.json`, траектория): выводы, затронутые ID, суммы, валюты, доказательства, TP/FP/FN, число инспекций, награда, последовательность действий. Итого 38/0/0. Валюты KZT, USD, JPY (0 знаков), KWD (3 знака) |
| То же на результатах containerd | 20 из 20, 0 расхождений |
| `crosscheck --live` на шести прогонах консоли | 0 расхождений: статусы, оценки, шаги и остаток бюджета, суммы и разрядность, каждая ссылка до строки исходного файла, ответ SQL. Живой повтор действий и новая оценка выполнены и совпали |

Попытки репетиции идут в режиме `closed`, и консоль их не публикует. Поэтому доверенная лаборатория повторяет
тот же снимок в режиме `train` и сравнивает свой экспорт с CLI-файлами.

## Прерывание и повтор (classic)

| Действие | Результат |
|---|---|
| SIGINT группе процессов `verify` (как Ctrl+C) через 25 с | launcher exit **130**, `launch.json` `interrupted`, контроллер остановился сразу, частичный отчёт `in_progress` |
| SIGINT только процессу launcher | launcher exit **130** и `interrupted`, но контейнер-контроллер **продолжил работу** ещё около 2 минут и дописал полный `verify/report.json` в каталог `interrupted` (190 из 256 тестов к моменту SIGINT, затем все 256) |
| Повторный `verify` после прерывания | новый каталог, прежние не изменены, 256 тестов, exit 2, 108 с |

Второй случай — дефект launcher (`offline.py` не останавливает дочерний `docker run` при собственном
прерывании). Это зона владельца релиза, в этом PR не исправлялось; обход описан в HANDOFF.md, раздел 8.
