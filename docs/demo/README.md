# Консоль жюри AuditLab

Локальная консоль для открытых завершённых прогонов: шаги аудитора, документы, суммы, доказательства, вердикт, сравнение пары и повтор. Работает офлайн: собранный фронтенд лежит в `auditlab/demo/static/`, Node для запуска не нужен, внешних шрифтов, CDN и сетевых запросов нет. Официальный тестовый запуск от веб-сервера не зависит.

## Запуск

Из корня репозитория, Python 3.11:

```sh
python -m pip install --require-hashes -r requirements.lock
python run.py demo                  # http://127.0.0.1:8765/
```

При первом старте строятся шесть прогонов с меткой «ОТКРЫТЫЕ ДАННЫЕ»:

- три **сгенерированные компании открытого набора** `datasets/open/train` по 240 строк и 76 документов:
  пограничная пара одного семейства, у которой последний зачёт стоит за минуту до (`E6476455…`, роль A) или
  через минуту после (`E651B6A6…`, роль B) исключаемой границы периода, и чистая компания `E04F4ED6…`;
- три маленьких ручных примера: пара `fixtures/foundation/S01`, `S02` и `auditlab/demo/scenarios/FX01`
  (оценка валютного платежа — мемориальная проводка `FX_VALUATION`/`FX_OFFSET`, как в генераторе).

Все шесть прогоняет настоящий раннер с обычным `reconcile`, настоящим оценщиком и SQL-сверкой. `run_id`
назначает раннер. Рабочий каталог — `runs/demo/` (в .gitignore), переопределяется `--root` или `AUDITLAB_DEMO_ROOT`.

Подключить настоящий экспорт раннера (только для чтения; принимаются только `mode: "train"`, `status: "completed"`, с `submission.json`, `score.json`, `trajectories.jsonl` и без `private/` — закрытые и незавершённые попытки в список не попадают):

```sh
python -m auditlab.demo --exports runs/exports serve
```

## Резервный показ без браузера

Те же данные, суммы и вердикты, что в UI (`show --json` выдаёт ровно ответ `GET /demo/runs/{id}`, это проверяет тест):

`run_id` назначает раннер и меняется от запуска к запуску: подставьте значения из `list`
(`S02_RUN` — строка эпизода S02, `FX01_RUN` — FX01, `NEW_RUN` — ID из ответа `change`).

```sh
python -m auditlab.demo list
python -m auditlab.demo show --run S02_RUN
python -m auditlab.demo change --source FX01_RUN --target payments/D9 --value 2026-11-15T00:01:00+05:00
python -m auditlab.demo show --run NEW_RUN
python -m auditlab.demo rescore --source NEW_RUN --replace fx/2026-11-15/USD/KZT --with fx/2026-11-14/USD/KZT
python -m auditlab.demo replay --run S02_RUN --check
python -m auditlab.demo crosscheck --live
```

`crosscheck` сверяет каждое показанное значение консоли с файлами экспорта, не используя код консоли:
статус, TP/FP/FN, награду, число шагов, действия и остаток бюджета по шагам, сумму, валюту и разрядность
по `manifest.currency_exponents`, каждую ссылку доказательства до строки исходного файла и ответ SQL-сверки.
`--live` дополнительно выполняет записанные действия заново через публичную среду и заново оценивает сдачу.
`crosscheck --rehearsal results/verify-…/verify/rehearsal` повторяет reconcile на 20 снимках внутренней
репетиции и сравнивает экспорт консоли с CLI-попытками (`final.json` и траекторией). Это доверенная команда,
ей нужен эталон снимков. Результаты — в [RC2_AGENT_CHECK.md](RC2_AGENT_CHECK.md).

Успех `crosscheck` (код 0, JSON `ok: true`) требует хотя бы одного проверенного запуска.
Пустой набор или отсутствующие файлы репетиции дают «не проверено» и код 2. Повреждённый
завершённый экспорт, пустой журнал, отсутствующая сдача или расхождение дают код 1.
`--live` требует успешного пересчёта оценки: отсутствие доверенного эталона не считается совпадением.
Закрытые и незавершённые попытки не публикуются и не включаются в эту проверку консоли.


Ошибка запуска опыта возвращает JSON с кодом и сообщением, например `no_rate_for_date` или
`unsupported_counterfactual` (перенос платежа в другой отчётный период). В браузере тот же код
показывается с русским объяснением. Из офлайн-комплекта эти команды запускаются в runtime-образе:
см. [DEFENSE.md](DEFENSE.md).

## Экраны

| Экран | Что видно |
|---|---|
| Запуски `#/` | Компания, период, политика, статус, метка, награда, связи «исходная → опыт/копия». Только завершённые открытые попытки. Пустое состояние с командой запуска. |
| Расследование `#/runs/{id}` | Слева шаги, в центре конкретная строка файла (`public/ledger.csv · строка 6`) с подсветкой поля-операнда, справа вывод: сумма агента → операнды → правило; строки «Агент», «Оценщик», «Консоль», «SQL» подписаны раздельно. Пустая сдача: «Ошибок не заявлено». |
| Сравнение `#/compare/{a}/{b}` | Изменённый факт, прогноз судьи, фактическая разница, обе суммы с операндами, оба ответа и оценки, построчные различия документов. Для копии сдачи — какой операнд больше не подтверждён. |
| Повтор `#/runs/{id}/replay` | «ПОВТОР ЗАПИСИ»: пошаговое воспроизведение сохранённого журнала. Кнопка выполняет «ЖИВОЙ ПЕРЕСЧЁТ»: действия заново через публичную среду и новая оценка; на экране время выполнения и длительность. |

Скриншоты: [docs/demo/screenshots](screenshots).

  резервные команды без браузера.

- [HANDOFF.md](HANDOFF.md) — комплект передачи получателю: требования, проверка хеша, первый офлайн-запуск,
  ожидаемые файлы и коды, обе конфигурации Docker, диагностика, повтор после прерывания.
- [RC2_AGENT_CHECK.md](RC2_AGENT_CHECK.md) — агентская проверка опубликованного `v0.1.0-rc.2` на обоих
  хранилищах Docker и сверка консоли с CLI. RC2 — исторический кандидат: блокер #23 в нём не исправлен.
- [RC1_AGENT_CHECK.md](RC1_AGENT_CHECK.md) — агентская проверка `v0.1.0-rc.1`. Ни одна агентская
  проверка не заменяет прохождение README новым человеком.

**Учебная демонстрация и измерения различаются.** Консоль показывает отдельные показательные прогоны на
открытых учебных данных (метки «ОТКРЫТЫЕ ДАННЫЕ», «ЖИВОЙ ОПЫТ», «КОПИЯ СДАЧИ»). Их награда объясняет
механику оценки и не является средним по набору или конкурсным баллом. Измеренные результаты внутренней
репетиции (20/80/20, ресурсы) находятся в отчёте `--suite rehearsal` и `evidence-summary.json`; об этом
напоминает плашка на странице запусков.

## Что дал какой модуль

У каждой попытки на экране и в `show` есть строка «движок». Прогоны открытых данных и живые опыты прогоняются теми модулями, которые есть в checkout; `auditlab/demo/engines.py` берёт настоящие и на учебную замену (`auditlab/demo/standin.py`, «учебная замена») переходит только при их отсутствии. Ошибка подключённого модуля возвращается кодом `infrastructure_error`, без отката на замену.

| Часть | Подключённый модуль |
|---|---|
| Публичная среда | `auditlab.environment.open_session` |
| Аудитор | `auditlab.policies.make_policy("reconcile")` |
| Раннер | `auditlab.runner.make_env("train")`; ID назначает настоящий раннер |
| Оценщик | `auditlab.evaluator.score_submission`; индивидуальный вердикт выводится из TP/FP/FN только когда однозначен и помечается «выведено из итога» |
| Независимая сверка | `auditlab.verifier.verify_snapshot` на отдельной копии `public/`; результат не заменяет вердикт оценщика |
| Изменение факта, сгенерированная компания | Настоящий `auditlab.generator`: тот же seed и nonce, изменён один параметр `settlement_timing` |
| Изменение факта, ручные примеры | Ограниченный учебный адаптер `demo-standin`, правила и отказы ниже; это не универсальный генератор изменений |

## Границы изменения факта и денежных выводов

**Сгенерированные компании** (`engine.generator = auditlab.generator …`). Доверенная лаборатория хранит seed
и конфигурацию генератора в `runs/demo/trusted/` (в `console.json` и ответы API они не попадают). Перед
изменением генератор воспроизводит исходную компанию **побайтно**, иначе `generator_mismatch`. Затем он
строит варианты `settlement_timing` `before` / `at` / `after` с тем же seed и nonce. Менять можно только
строку журнала последнего зачёта (две строки `UNAPPLIED`/`AR`) и только на дату, которую ставит генератор
для соседнего варианта; иначе `generator_unsupported` с перечнем допустимых строк или дат. Эталон новой
компании выдаёт генератор, консоль его не выводит. Все прочие ошибки компании (например, дубль счёта)
генератор сохраняет.

**Ручные примеры** (`fixtures/foundation`, `FX01`):
Доверенная лаборатория требует исходный учебный эталон. Весь исходный ответ должен
воспроизводиться поддержанными расчётами распределения и FX; наличие любого другого
типа ошибки, включая дубли счетов и границу периода, блокирует изменение с кодом
`unsupported_counterfactual`. Экспорт без доверенного эталона доступен для просмотра,
но изменение получает `truth_unavailable`. Веб-процесс эталон не читает.

Поддержаны две операции: перенос даты полного сбалансированного зачёта
`UNAPPLIED → AR` и перенос даты платежа **внутри одного целевого периода**.
Требуются положительные платежи с единственным назначенным счётом и полным индексом
остатка в той же валюте. Перенос первичного признания, переход платежа в другой
период, смешанные валюты распределения и неподдерживаемые исходные ошибки отклоняются
до публикации новой компании. Имена компании и ID не дают права обойти проверку.
Исходный экспорт и его эталон остаются неизменными. Для более общих изменений нужен
отдельный адаптер полноценного генератора, сохраняющий все независимые ошибки.

UI и CLI берут денежную разрядность из `manifest.currency_exponents`: 12 000 minor JPY
означают 12 000 JPY, а 20 000 minor KWD — 20,000 KWD. При отсутствии разрядности
отображаются исходные минимальные единицы с явной пометкой. Несовпадение валюты не
может получить зелёное подтверждение только из-за одинакового целого числа.
Совпадение независимой арифметики отдельно от зачёта доказательств: верная сумма
с неполными ссылками по-прежнему отклоняется оценщиком. При пустой сдаче видны все
найденные независимой сверкой ошибки; локальный расчёт консоли явно ограничен
распределением и FX.


Учебная сессия обязана отвечать в формате настоящей среды (страницы `policy` — пары `id/value`, `get_record policy` — значение правила, калькулятор — десятичная строка); тест `PublicInterface` сравнивает их ответ в ответ, когда среда есть в checkout.

## Граница доступа

- Веб-процесс (`server.py`, `service.py`, `store.py`, `snapshot.py`) читает только каталоги экспортов и статусы операций; тест запрещает в этих модулях обращения к эталону.
- Экспорт закрытого режима и экспорт с каталогом `private/` в консоль не попадают.
- Новые опыты, копии сдачи и повторная оценка выполняет доверенный процесс `python -m auditlab.demo.lab` с учебным эталоном в `runs/demo/trusted/`. Публикация — атомарное переименование готового каталога; существующая попытка не перезаписывается; тот же ключ операции возвращает тот же опыт.

## Формат экспорта

Образец: [sample_export/TRAIN-S02-reconcile](sample_export/TRAIN-S02-reconcile). Обязательные файлы — по INTERFACES.md: `run.json` (run_id, episode_id, policy, mode, status), `public/`, `trajectories.jsonl` (§11), `submission.json`, `score.json`. Необязательные, которые консоль использует при наличии: `console.json` (метка, компания, период, движки, `parent_run_id`, `change`, `prediction`, `derived_from`; ключи ядра `run.json` не переопределяет), `score.json.per_finding[{index, matched, reason}]`, `verifier.json`.

## Разработка фронтенда

```sh
npm --prefix web ci
npm --prefix web run dev       # Vite с прокси /demo → 127.0.0.1:8765
npm --prefix web test          # денежные единицы по manifest, без предположения exp=2
npm --prefix web run build     # tsc + сборка в auditlab/demo/static
python -m unittest discover -s tests/demo -v
```
