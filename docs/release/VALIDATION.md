# Проверка релизного кандидата AuditLab

Цель — сильная конкурсная среда с доказуемой финансовой корректностью и воспроизводимым запуском. Победа и баллы закрытых испытаний не выводятся из внутренних тестов.

## Фактически измерено

Финальный прогон опубликованного [v0.1.0-rc.1](https://github.com/Mustiks07/AuditLab/releases/tag/v0.1.0-rc.1) на **свежем GitHub-hosted Ubuntu 24.04**: commit
`b16456cab15d65c75dac5fc9d249af2d2ee8c055`, [run 44577035303](https://github.com/Mustiks07/AuditLab/actions/runs/44577035303).
Сборка выполнена на другой машине. Перед `docker load` все три image ID отсутствовали.
Проверяющая машина не устанавливает зависимости проекта. Контейнеры работают с `network none`, без GPU и registry pulls.

- 237 тестов прошли без пропусков; 20 снимков, 80 запусков и 20 пар прошли.
- У контроллера, 60 обычных политик и 40 запусков verifier подтверждены реальные cgroup v2 memory/CPU/cpuset/PID/swap limits. Используются одни два CPU; controller и последовательный sibling имеют по 2 GiB RAM, swap=0.
- Пики: controller **188 805 120 B**, policy **24 797 184 B**, verifier **149 139 456 B**. Это отдельные пики контейнеров, не измерение всего хоста или Docker daemon.
- Максимум полного измеренного запуска политики с подготовкой/очисткой — **1,383 с**; загрузка образов **8,542 с**; общий проверяющий контейнер **165,113 с**.
- Payload комплекта **309 646 082 B**, меньше 1 GB.
- Демонстрация и replay контрольной S02 проверены отдельно на `cf75e3b` в контейнере без сети: HTTP, JS/CSS, повтор наблюдений и оценки успешны.

У reconcile ложных обвинений на пяти чистых компаниях нет. Это внутренний зафиксированный набор; опубликованные результаты не означают качество на неизвестных хозяйственных историях. Oracle получает закрытый эталон и не является обычным аудитором.

Финальный CI прошёл полностью; итоговый checker даёт `internal_rehearsal_passed`, failures=[], missing=[]. [Машиночитаемые измерения RC1](evidence/rc1-summary.json) сохраняют SHA и image IDs. [Более ранний прогон](evidence/b18ed65-summary.json) оставлен как историческое свидетельство, включая исправленный дефект PID-checker. Здесь приведены результаты RC1, а не последующих коммитов разработки.

## Матрица SPEC §14

«Покрыто» — имеются конкретные успешные внутренние испытания, а не сертификат организатора. Общий строгий `run.py verify --suite rehearsal` сохраняет exit 2, пока полная приёмка не закрыта; отдельный checker подтверждает только исполняемые внутренние 20/80/20 и ресурсы.

## Независимые проверки и исправления

[Ручные финансовые материалы](../reviews/manual-financial/README.md) подтверждают шесть находок по public, отдельный чистый возврат и 78 адресуемых evidence-ссылок. Их исходные train/dev сохранены побайтно. Новый профиль 1.1 публикует исключающую границу и версии правил, содержит явно проверенный полностью чистый возврат.

В PR #12 исправлены DST-расчёты, валютные единицы/сопоставление консоли, недопустимые counterfactuals, транспорт/deadline/cleanup, malformed truth и ложное подтверждение replay по одному публичному нулевому reward. Версии: generator 1.3, runner/evaluator 1.1, verifier-rules 1.1, tzdata 2026.6.

Приоритет оставшейся работы: формальные публичные схемы и внешний адаптер; независимая проверка канонических семейств данных; приёмка архива человеком, который не участвовал в разработке. Никакой из этих пунктов не маскируется высоким F1 внутреннего reconcile.
