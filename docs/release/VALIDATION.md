# Проверка релизного кандидата AuditLab

Цель — сильная конкурсная среда с доказуемой финансовой корректностью и воспроизводимым запуском. Победа и баллы закрытых испытаний не выводятся из внутренних тестов.

## Текущая интеграция после независимого исследования

PR #28, #22, #26, #27 и #29 приняты на GitHub после проверки актуальных head/base.
Авария глубокой сдачи #23 исправлена; опубликованы схемы и внешний адаптер;
финансовые оригиналы и исследование кейса сохранены с командами воспроизведения.
Дальнейшие исправления собраны в PR #30: генератор 1.5, полная исходная книга,
чистые контрпримеры, достоверность сохранения/метрик, отмена Docker-запуска и
суммарный лимит контейнеров 3 GiB. Старые измерения RC1/RC2 не приписываются этой версии.

Для текущего кода 24 внутренних группы вычисляются по конкретным выполненным
проверкам и связанным с SHA свидетельствам: [правила](ACCEPTANCE_MAPPING.md).
Быстрый прогон не заменяет 20 исходных книг и 20 пар, фактические ресурсы или
приёмку получателем. Новая полная офлайн-репетиция должна сопровождать точный
исходный SHA нового кандидата. Официальный адаптер, человеческая приёмка и
память всей ОС/daemon остаются отдельными непроверенными пунктами.

## Опубликованный кандидат RC2: исторические измерения

[v0.1.0-rc.2](https://github.com/Mustiks07/AuditLab/releases/tag/v0.1.0-rc.2),
source `0791995d2d8ff3d15d5043197fc6079be01e6a6f`,
[успешный CI 44606305454](https://github.com/Mustiks07/AuditLab/actions/runs/44606305454).
Один комплект проверен на двух отдельных свежих хостах; все три образа отсутствовали
до загрузки. На **каждом** хосте: 256 тестов без пропусков, 20 снимков, 80 запусков,
20 пар, фактические ресурсные свидетельства контроллера, 60 обычных политик и 40 verifier.
Оба internal checker дают exit 0, failures=[], missing=[]; строгая полная приёмка остаётся exit 2.

| Хранилище | Docker | Тесты | Снимки / попытки / пары |
|---|---|---:|---:|
| classic | 28.0.4 | 256 | 20 / 80 / 20 |
| containerd | 29.0.1 | 256 | 20 / 80 / 20 |

Payload **314 973 218 B**. В [машиночитаемом отчёте RC2](evidence/rc2-summary.json)
раздельно сохранены фактические image IDs, время, пики контейнеров и результаты политик.
Это повтор одного внутреннего набора на двух хранилищах, а не 40 независимых компаний.
Память ОС и Docker daemon не включена в отдельные пики контейнеров.

Устранены найденные агентской проверкой две причины отказа на containerd: потеря OCI-записей
при сохранении без тегов и различие config ID / OCI manifest digest. Runtime выбирается
только по проверенной неизменяемой идентичности. Демо включает исправления консоли PR #17
и [сценарий защиты](../demo/DEFENSE.md). Готов [чек-лист получателя](../demo/ACCEPTANCE_CHECKLIST.md);
его прохождение новым человеком остаётся «не проверено». Матрица SPEC ниже не закрывается
автоматически ни новым числом тестов, ни второй конфигурацией Docker.

## Предыдущий кандидат RC1: сохранённые измерения

Последующие изменения разработки и их отдельные измерения приведены в
[приёмке работ 20 ноября](../reviews/integration-2026-11-20.md): PR #20/#21 приняты,
совместная версия прошла 274 теста и 20/80/20 на обоих хранилищах. Это не новая
публикация RC2 и не закрытие блокера #23.

Финальный прогон опубликованного [v0.1.0-rc.1](https://github.com/Mustiks07/AuditLab/releases/tag/v0.1.0-rc.1) на **свежем GitHub-hosted Ubuntu 24.04**: commit
`b16456cab15d65c75dac5fc9d249af2d2ee8c055`, [run 44577035303](https://github.com/Mustiks07/AuditLab/actions/runs/44577035303).
Сборка выполнена на другой машине. Перед `docker load` все три image ID отсутствовали.
Проверяющая машина не устанавливает зависимости проекта. Контейнеры работают с `network none`, без GPU и registry pulls.

- 237 тестов прошли без пропусков; 20 снимков, 80 запусков и 20 пар прошли.
- У контроллера, 60 обычных политик и 40 запусков verifier подтверждены реальные cgroup v2 memory/CPU/cpuset/PID/swap limits. Используются одни два CPU; controller и последовательный sibling имеют по 2 GiB RAM, swap=0.
- Пики: controller **188 805 120 B**, policy **24 797 184 B**, verifier **149 139 456 B**. Это отдельные пики контейнеров, не измерение всего хоста или Docker daemon.
- Максимум полного измеренного запуска политики с подготовкой/очисткой — **≈1,382 с**; загрузка образов **≈8,541 с**; общий проверяющий контейнер **≈165,112 с**.
- Payload комплекта **309 646 082 B**, меньше 1 GB.
- Демонстрация и replay контрольной S02 проверены отдельно на `cf75e3b` в контейнере без сети: HTTP, JS/CSS, повтор наблюдений и оценки успешны.

| Политика | TP / FP / FN | micro F1 | Средняя награда |
|---|---:|---:|---:|
| random | 0 / 0 / 38 | 0 | −0,5035 |
| reconcile | 38 / 0 / 0 | 1 | 0,9512 |
| flag_all | 0 / 600 / 38 | 0 | −1 |
| oracle, доверенный | 38 / 0 / 0 | 1 | 1 |

У reconcile ложных обвинений на пяти чистых компаниях нет. Это внутренний зафиксированный набор; опубликованные результаты не означают качество на неизвестных хозяйственных историях. Oracle получает закрытый эталон и не является обычным аудитором.

Финальный CI прошёл полностью; итоговый checker даёт `internal_rehearsal_passed`, failures=[], missing=[]. [Машиночитаемые измерения RC1](evidence/rc1-summary.json) сохраняют SHA и image IDs. [Более ранний прогон](evidence/b18ed65-summary.json) оставлен как историческое свидетельство, включая исправленный дефект PID-checker. Здесь приведены результаты RC1, а не последующих коммитов разработки.

## Историческая матрица до PR #28/#22 и генератора 1.5: SPEC §14

На исходном a301b16 при проверке работ 20 ноября был найден блокер (впоследствии исправлен в PR #28):
[#23](https://github.com/Mustiks07/AuditLab/issues/23). Синтаксически корректный
JSON `submit` с `findings` глубины 600 срывает финализацию runner: состояние
`done`, `final=None`, пустая траектория и исключение вместо результата. Проверено
через внешний JSONL-процесс на Python 3.11.14. Это существующий дефект, который
успешная репетиция обычных политик не покрывает. До исправления API-03/API-04
и MAT-03 нельзя считать полностью принятыми. Опубликованный RC2 остаётся
историческим кандидатом; его успешные измерения не отменяют этот контрпример.

«Покрыто» — имеются конкретные успешные внутренние испытания, а не сертификат организатора. Общий строгий `run.py verify --suite rehearsal` сохраняет exit 2, пока полная приёмка не закрыта; отдельный checker подтверждает только исполняемые внутренние 20/80/20 и ресурсы.

## Независимые проверки и исправления

[Ручные финансовые материалы](../reviews/manual-financial/README.md) подтверждают шесть находок по public, отдельный чистый возврат и 78 адресуемых evidence-ссылок. Их исходные train/dev сохранены побайтно. Новый профиль 1.1 публикует исключающую границу и версии правил, содержит явно проверенный полностью чистый возврат.

В PR #12 исправлены DST-расчёты, валютные единицы/сопоставление консоли, недопустимые counterfactuals, транспорт/deadline/cleanup, malformed truth и ложное подтверждение replay по одному публичному нулевому reward. Версии: generator 1.3, runner/evaluator 1.1, verifier-rules 1.1, tzdata 2026.6.

Текущие оставшиеся действия: повторить общую офлайн-приёмку нового SHA, выпустить
архив с его свидетельствами и передать именно этот файл независимому человеку
по #15. Официальные результаты жюри и сравнение с другими командами остаются
неизвестными независимо от внутреннего F1.
