`datasets/open` сохранён как исторический набор для повторения ранних результатов
и экранной контрольной пары. Его нельзя смешивать с результатами нового набора.

## Одна команда проверки

Для получателя **готового RC5**, после проверки хеша и распаковки по HANDOFF:

```sh
python3.11 offline.py verify --suite quick --output-root ./results
```

Предварительные системные условия: Linux x86_64, Python 3.11, локальный Docker
Engine, cgroup v2 и доступ к Docker socket. Launcher загружает поставленные образы;
сеть и установка Python-пакетов проекта не нужны. Код **0** означает успешные
исполненные проверки и подтверждённые ресурсные ограничения этого прогона;
**1** — ошибку; **2** — неполную проверку или неподтверждённые ресурсы. В RC5
быстрый набор содержит 528 тестов. Это локальная самопроверка, не официальный балл.

Для разработчика из checkout с зависимостями из `requirements.lock` и собранным
образом политики (`AUDITLAB_POLICY_IMAGE`) общая команда — `python run.py verify`.
Без `--require-complete` она возвращает **0**, если доступные проверки прошли,
даже если полная матрица приёмки имеет статус `incomplete`. Строгая проверка
`python run.py verify --require-complete` требует подтверждения всех обязательных
пунктов и возвращает 2 при пробелах. Разница между статусом отчёта и кодом выхода
существенна; код 0 сам по себе не означает полного прохождения кейса.

## Открытые траектории

В корневом файле — реальные прогоны `reconcile` на **всех 20 компаниях `open-1.3`**
через официальный адаптер. Каждый аудитор выполнялся в отдельном Docker-контейнере
без сети и без монтирования каталога эпизода. Для обоих разделов включён режим
`train`: это открытые материалы, поэтому терминальная награда доступна. Режим не
означает дообучения модели. Закрытые данные не включены в `observation`.

Каждая строка имеет ровно семь полей §09: `episode_id`, `step`, `action`,
`observation`, `reward`, `terminated`, `truncated`. Шаг **0** — начальный ответ
`reset` с действием `{"name":"reset","args":{"mode":"train"}}`; он не расходует
бюджет. Шаги 1–100 соответствуют вызовам `step`; observation в каждой строке —
ответ на действие этой строки. Начальная конфигурация компании закреплена в
рецепте набора, а `episode_dir` выбирает готовый снимок без новой генерации.

Из корня checkout после установки закреплённых зависимостей можно независимо
повторить все записанные действия и сравнить наблюдения и награды:

```sh
python tools/export_trajectories.py check
```

Код 0 — все 20 законченных траекторий совпали; 1 — повреждение, неполнота или
расхождение. Это повтор записанных действий, а не новый запуск политики.
Для нового изолированного прогона, с подготовленным локальным образом политики:

```sh
python tools/export_trajectories.py export --policy-image YOUR_LOCAL_POLICY_IMAGE --output artifacts/open-trajectories
```

Выходной каталог должен быть новым. В нём будут JSONL и манифест с хешами,
версиями, принадлежностью train/dev и ID реально использованного образа.
CI повторяет изолированный экспорт и сравнивает JSONL побайтно.
Эти файлы являются материалами сдачи в Git, отдельно от неизменного архива RC5.

## Закрытая генерация с секретом жюри

Открытый детерминированный генератор с маленьким пространством seed можно
перебирать, если известна конфигурация. Для закрытых эпизодов используйте профиль
1.3 с **случайным `episode_key`**, который хранится только у доверенной стороны.
Создать приватную конфигурацию без вывода ключа в терминал:

```sh
python tools/make_judge_config.py ../auditlab-judge.private.json
```

На POSIX файл создаётся с правами 0600; на Windows ограничьте ACL учётной записью
жюри. Существующий файл, включая симлинк, не перезаписывается. Сохраните этот файл
для воспроизведения и передавайте его содержимое как `config` генератору:

```python
import json
from pathlib import Path
import judge_adapter

config = json.loads(Path("../auditlab-judge.private.json").read_text(encoding="utf-8"))
judge_adapter.generate_episode(123, config, "private-episodes/episode-001")
```

Для повторения используйте тот же seed, ту же конфигурацию и новый выходной каталог.
Приватную конфигурацию, каталог `private/` и журнал жюри нельзя монтировать аудитору
или публиковать. Ключ не генерируется скрыто внутри `reset` или `{}`: сам контракт
остаётся детерминированным по явно сохранённым входам. Вызов без ключа — открытый
воспроизводимый режим; он не обещает защиты от перебора seed.

## Каталог эпизода и переименование ID

`generate_episode` записывает `public/{manifest.json,ledger.csv,invoices.jsonl,
payments.jsonl,fx.csv,policy.json}` и `private/{truth.json,provenance.json,...}`.
Адаптер загружает переданный `episode_dir` без исправления или подмены файлов.

По [определениям организаторов](https://genesis-exe.com/fintech-checks.html), раздел
«Правила безопасного преобразования», меняются **все ссылки согласованно**, включая
дополнительные документированные поля. Для AuditLab карта следующая:

| Поле или ссылка | Пространство и правило замены |
|---|---|
| `ledger.row_id` | `row_id` |
| `invoices.doc_id`, `payments.doc_id` | `doc_id`; сохранить уникальность документов |
| `invoice_id`, `payment_id`, `entity_id` в документах и проводках | Соответствующее пространство; сохранять `null` |
| `payments.invoice_refs[]` | `invoice_id` |
| `payments.allocation_instructions[].invoice_id` | `invoice_id`; суммы и порядок назначений сохраняются |
| `payments.settlement_index.unapplied_row_ids[]` | `row_id`; каждая ссылка должна разрешаться в `ledger` |
| `affected_ids`: `invoice/<id>`, `payment/<id>` | Заменить часть после первого `/` по карте соответствующего пространства |
| `evidence_ids` и `truth.issues[].evidence_sets`: `ledger/<id>` | Заменить часть после первого `/` по карте `row_id` |
| Там же: `invoices/<id>`, `payments/<id>` | Заменить часть после первого `/` по карте `doc_id` |
| `fx/DATE/SOURCE/TARGET`, `policy/<rule>` | Семантические ключи; не менять дату, валютную пару или имя правила под видом переименования ID |
| `episode_id`, `journal_id` | В нашем опубликованном протоколе остаются прежними; группировка двойной записи сохраняется |
| Закрытый `provenance` и исходная книга | Преобразуются только доверенным проверяющим с теми же картами, если входят в проверяемую копию |

Составная ссылка — типизированная ссылка, а не независимый суррогатный ID.
Например, переименование `row_id: R1 → X7` требует `ledger/R1 → ledger/X7`.
Matcher сравнивает итоговые строки точно; он не угадывает старые ID по новым.
Разные пространства не объединяются в одну карту при совпадении строк.

Самопроверка преобразованной копии, уже включённая в исходники RC5:

```sh
python -m review.jury_compatibility_v3.check_links PATH_TO_EPISODE
```

Коды: 0 — ссылки согласованы; 1 — перечислены разорванные ссылки; 2 — вход
нечитаем. Полные правила и измерения: [ID_RULES.md](reviews/jury-compatibility-v3/ID_RULES.md).
Неполное переименование, оставившее старые ссылки в эталоне или индексе, — отдельный
отрицательный контроль, а не свидетельство прохождения корректной пары.
