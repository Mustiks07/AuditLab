# Поиск слабостей финансового аудитора

Исходный `origin/main` — `611163e75468f4af95cfa115f033e7a9f8c81145`. Отдельный
[PR по полному пропуску #48](https://github.com/Mustiks07/AuditLab/pull/48) —
`9328013703056bf41abb6cc6929e06a06ded7f05`. План локального опыта использует
профиль 1.1, генератор 1.6 из base и явный список [конфигураций и seed](local-plan.json).
Когда #48 попадёт в main, новый план может запросить `allocation_mode: "omitted"`
для отдельного расчёта. Результаты старого плана останутся отдельным опытом.

## Воспроизведение

Запустить из корня репозитория с зависимостями из `requirements.lock`.

```sh
git fetch origin review/agent-generalization feature/llm-auditor-experiments
git worktree add --detach ../AuditLab-curriculum-reviewer 079bd8c46ec1e82c18378bf162b883eddace4745
python -m unittest discover -s tests/curriculum -v
python -m unittest discover -s tests/foundation -v
python -m unittest discover -s tests/genesis_acceptance -v
python -m auditlab.research.curriculum --plan docs/research/financial-curriculum/local-plan.json --reviewer ../AuditLab-curriculum-reviewer --output artifacts/c41-random --policy random
python -m auditlab.research.curriculum --plan docs/research/financial-curriculum/local-plan.json --reviewer ../AuditLab-curriculum-reviewer --output artifacts/c41-reconcile --policy reconcile
python docs/research/financial-curriculum/summarize.py artifacts/c41-random artifacts/c41-reconcile
git diff --exit-code 611163e -- datasets/open docs/release
```

Для повторного запуска передать новый каталог `--output`. Seed выбора — `4103701`.
Исследуются только исходные train-семейства. Оба способа получают до девяти
кандидатов и до 18 запусков, по два повтора на проверенного кандидата. Равномерная
ветвь идёт по общей seeded-перестановке без возвращения. Адаптивная выбирает страту
по сглаженной частоте пропусков и поправке на число предложений. Эта поправка даёт
редко проверявшимся стратам шанс на выбор. Кандидат принимается, если оба повтора
завершились валидной сдачей и в каждом есть пропуск хотя бы одного вывода.
Ложные обвинения записываются в квитанции. Критерий локального опыта учитывает пропуски.

Перед запуском проверяющий из [PR #46](https://github.com/Mustiks07/AuditLab/pull/46)
отдельно рассчитывает сумму по публичным записям и фиксирует хеш ответа. Затем он
проверяет чистую исходную книгу, переход к дефектной книге и совпадение с эталоном.
Публичный свидетель обнаруживает ссылки последовательными листингами и укладывается
в лимиты Genesis. Локальные политики запускаются через закрытый runner с правилами
Genesis и получают результаты публичных действий. Учёт времени и шагов ведёт runner.

Сокращатель удаляет целые связанные группы операций, защищая все эталонные ошибки
и их доказательства. Каждый вариант проходит проверку исходной книги и перехода.
Затем аудитор заново расследует вариант три раза. Принимаются только варианты,
сохранившие целевой сбой как минимум в двух повторах и с частотой не ниже исходной.
Имена попыток и хеши публичных данных привязывают замеры к соответствующим снимкам.
Размер проверяемого сокращения может быть меньше минимального размера обычной компании.

## Подключение Claude Pro 1

```sh
git worktree add --detach ../AuditLab-curriculum-claude 61136963764f5d35124ea2177bbbe3d45b8ff932
python -m auditlab.research.curriculum --plan artifacts/provider-plan.json --reviewer ../AuditLab-curriculum-reviewer --claude-config artifacts/claude-config.json --output artifacts/c41-claude
```

Конфигурация доверенной стороны передаёт `runner_checkout`, `protocol_id`
(`genesis-official-60s`), `agent`, `provider`, `docker`, `max_attempt_cost_micros`,
`max_provider_calls` и `max_wall_seconds`. Используются объекты `agent`, `provider`
и `docker` из [исполнителя PR #47](https://github.com/Mustiks07/AuditLab/pull/47).
Нужны собранные локально образы из этого PR, доступный Docker, модель и цены для
расчёта верхней оценки, а также ключ через переменную `provider.api_key_env`.
В каждом разделе `search` и `reduction` задаются `cost_budget_micros` и
`max_attempt_cost_micros`. Резерв поиска задаётся **на каждую ветвь**. Верхний предел
всего опыта до фактических списаний равен двум бюджетам поиска плюс бюджет сокращения.
Если исполнитель не смог подтвердить расход, поиск прекращает запуск новых попыток.
Итоговая стоимость зависит от телеметрии и точности верхней оценки провайдера.

Офлайн проверены привязка к закреплённому исполнителю и форма его квитанции.
Заглушки, невалидные сдачи, тайм-ауты и ошибки транспорта не засчитываются как
измеренный финансовый провал. В этой среде `ANTHROPIC_API_KEY` отсутствует,
Docker Engine недоступен, поэтому вызовов API, реального счёта провайдера и
измерений уязвимости внешней модели нет. Локальные результаты получены с реальными
встроенными политиками `random` и `reconcile`.

Подготовка SFT использует `load_curriculum` и `build_sft` того же PR. Команда
читает доверенные снимки только для проверенных train-примеров, создаёт отдельно
помеченные учительские траектории и записывает `sft/dataset.jsonl` с манифестом.
Сохранять дерево опыта целиком, чтобы ссылки `episodes[].episode_ref` разрешались
относительно каталога `curriculum`.

```sh
python -m auditlab.research.curriculum.prepare_teacher --runner ../AuditLab-curriculum-claude --curriculum artifacts/c41-random/curriculum/curriculum.json --output artifacts/c41-teacher
```

## Артефакты и границы экспорта

| Файл | Что хранится |
|---|---|
| `experiment.json`, `candidates/*/candidate.json` | SHA исходников, хеш плана и разбиения, конфигурации и provenance, лимиты и критерии измерения |
| `search/search.json`, `*/attempt.json` | Все предложенные кандидаты, статусы, причины, ссылки на валидацию и расследования, запуски и расходы |
| `failure.json`, `reduction/reduction.json` | Совпадение целевого сбоя, обе группы свежих повторов, интервалы, исходный и сокращённый снимки |
| `*/validation.json`, `*/answer_before_truth.json` | Независимая проверка, арифметика, хеш до чтения эталона и шаги публичного свидетеля |
| `curriculum/curriculum.json` | Версия экспорта, канонические отпечатки, происхождение, хеши публичных файлов и проверок, стоимость отбора |

`curriculum/public/<split>/<snapshot_sha256>` содержит шесть стандартных файлов.
Путь паблика не раскрывает имя сценария. Учительский JSON лежит в `trusted/train`.
В dev выдаются публичные снимки и хеши доверенных квитанций. `test` не передаётся
в поиск, в сокращение или в экспорт. Канонизация сравнивает итоговую и чистую
исходную книгу независимо от ID и порядка. Явное родство удерживает исправление,
переименование и сокращение в разделе родителя. Точные совпадения полных цепочек
считаются отдельно. Общее бухгалтерское правило может повторяться в любых разделах.

Конфигурация `test-partition-fixture` из открытого локального плана проверяет
механизм удержания. Финальные закрытые семейства Claude Pro 2 в этот опыт не входили.

## Результаты и ограничения

| Аудитор | Адаптивный поиск | Равномерный поиск | Локальная стоимость |
|---|---:|---:|---:|
| `random` | 4 кандидата, 8/18 пропусков | 4 кандидата, 8/18 пропусков | 0 |
| `reconcile` | 0 кандидатов, 0/18 пропусков | 0 кандидатов, 0/18 пропусков | 0 |

В таблице пропуск — попытка с одним или несколькими пропущенными выводами.
Оба метода приняли одни и те же четыре случая `random`. Преимущество адаптации
на этом пуле не измерено. Критерий обнаружил пропуски частичного зачёта, границы,
дубликата и FX. Он не анализирует ложные обвинения как самостоятельную цель.

На seed `41063` независимый расчёт дал `5 280 000 − 3 168 000 = 2 112 000`
тиын KZT. Сокращение сохранило пропуск этой ошибки в 3/3 до и 3/3 после при
шести новых запусках. Книга сократилась с 240 до 6 проводок и с 76 до 2 документов.
Публичный свидетель перешёл с десяти действий на шесть. Интервал Уилсона
`[0,44; 1]` для каждой тройки показывает ограниченность выборки. Удаление групп
жадное, минимальность по всем возможным переписываниям не проверялась.

Проверены восемь производных вариантов в двух семьях. При смене ID или добавлении
законного возврата оставались 20 000 KZT. Зачёт перед границей убирал находку.
Смена валюты договора меняла результат с `2 000 000` тиын KZT на `20 000` JPY.
Размеры всех пар были 240 × 76. У переименованных записей сохранена грамматика ID
генератора. В публичных данных остаётся легко узнаваемая фиксированная схема
50 000/30 000. Простая эвристика из `summarize.py` обнаружила по ней 6/6
дефектных производных и ошибочно обвинила оба исправленных случая. Проверка
даты второго транша особенно проста именно в этой узкой контрольной семье.

Экспорт `random` включил 10 train и 4 dev, удалил по одному дубликату оформления
из каждого раздела. Два чистых train-контроля заданы планом отдельно от бюджета
поиска. Закреплённый исполнитель Claude Pro 1 создал 10 принятых офлайн SFT-записей
и 44 публичных действия в учительских траекториях. Два независимых запуска дали
одинаковый SHA-256 `e5e724b27a915e4f69d351d11c22f9ade018e02ccc8b6c7755293ea24b993000`
для `dataset.jsonl`. Для воспроизводимых ID вызовов у доверенного скриптового
учителя фиксируется `PYTHONHASHSEED`. В трёх канонических представлениях не обнаружено совпадений
полных цепочек между разделами на данном плане. Подробные измерения и хеши —
в [local-results.json](local-results.json).

Код поиска и разбиения замерен на `0b7f65c56f3069e2a3fb2081fe80b2bf9c901cf3`.
Проверки Windows/Python 3.12 прошли для curriculum (26), foundation (3),
Genesis acceptance (6) и evaluator (76). Дополнительный полный прогон runner
выполнил 138 проверок с двумя пропусками и двумя сбоями. Оба сбоя повторились на
чистом base: в Windows отсутствует `os.sched_getaffinity`, а проверка срока записи
в не читающий канал заняла около 2,03 секунды при пороге 1,5. Полноценный Linux
или Docker-прогон на этой машине не выполнялся. В отдельном PR #48 прошли 54
теста симулятора, включая побайтовую регенерацию исторических наборов.

Приоритет следующего измерения — закрепить второй пул с другими суммами, долями и
чистыми соседними операциями, а затем запустить настоящий API-агент при известных
ценах и сравнить устойчивые пропуски и ложные обвинения отдельно. Тот же тип
ошибки на публично проверенных данных ещё не доказывает, что выбранные примеры
улучшат модель на закрытом тесте. Здесь измеряется качество внутренних
расследований по опубликованным правилам, конкурсный балл по ним не вычислялся.
