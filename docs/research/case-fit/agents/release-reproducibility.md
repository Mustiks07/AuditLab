## Сборка, проверка и предел доказательства

- `tools/build_release.py` требует чистый commit, Linux x86_64, Python 3.11 и **classic** build daemon. Берёт исходники через `git archive`, отбрасывает локальные рабочие каталоги и файлы секретов, отвергает ссылки в упаковываемом дереве. Закреплённые Python и Docker CLI образы, wheels с `--require-hashes`, установка с `--no-index` и build RUN с `--network none` отделяют подготовку от автономного исполнения. `SOURCE_REVISION` записывается в runtime. Byte-точное повторение исходного tar.gz можно проверить. Побайтовое совпадение всего пересобранного Docker/ZIP-комплекта не измерялось. [Сборщик](../../../../tools/build_release.py) · [Dockerfile](../../../../docker/release/Dockerfile)
- При загрузке classic читает `manifest.json` (`Config`, `RepoTags`) и адресует образ по config ID. Containerd использует OCI `index.json`, тег из `io.containerd.image.name` и OCI manifest digest. RC1 потерял две OCI-записи, поскольку `docker save` делался по анонимным ID. RC2 сохраняет по тегам и запускает по допустимому неизменяемому ID для хранилища. В проверяемом main #20 дополнительно проверяет каталоги и digest до `docker load`. Текущий CI настраивает containerd Docker `29.10.0`, исторический RC2 использовал `29.0.1`. Переключение хранилища требуется только для сборщика и исторического обхода RC1. [CI](../../../../.github/workflows/verify.yml) · [Launcher](../../../../offline.py) · [Проверка архива](../../../../tests/integration/test_image_archive.py)
- `offline.py check` проверяет четыре размера, хеша и каталоги без Docker. `verify` повторяет проверки, принудительно использует локальный Unix socket, загружает образы и запускает доверенный runtime. В эксперименте `--bundle` обозначает каталог распакованной поставки. Внешний опубликованный SHA-256 ZIP нужен для привязки к полученному от интегратора комплекту. Внутренние хеши лишь сравнивают содержимое с manifest из того же архива. [Инструкция поставки](../../../release/offline.md)
- Checker с `--bundle` и `--expected-revision` сверяет версию, хеши и decimal 1 GB payload, immutable image IDs, охват групп/эпизодов, отсутствие failures/skips, ≤60 с и наблюдаемые cgroup v2. Он принимает результаты уже проведённого запуска. Проверка полей отчёта сама не пересчитывает траектории и не измеряет ресурсы повторно. Для cgroup v1 или недоступных контроллеров допустимы функциональные результаты с ресурсами `not_checked` и exit 2. `run.py verify --suite rehearsal` остаётся `incomplete` / exit 2 при полном внутреннем наборе, пока матрица полной приёмки не закрыта. Exit 1 — провал. [Checker](../../../../tools/check_rehearsal_evidence.py) · [Матрица приёмки](../../../release/VALIDATION.md)
