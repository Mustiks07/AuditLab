## Награда и доказательства

В PDF с. 3 §05 и с. 5 §10 требуется общий матчинг, корректные крайние случаи
F1 и заданная стоимость инспекций. Реализация сравнивает тип, каноническое
множество affected IDs, валюту и целую сумму с опубликованным допуском 0.
Затем ищет полное покрытие хотя бы одного допустимого набора evidence.
Максимальное сопоставление инъективно, повтор остаётся FP. Стоимость
0.002 применяется на терминальном переходе, расчёт и clipping сделаны через
`Fraction`. Стилистика объяснения исключена из вычисления оценки.
[Формула и матчинг](../../../../auditlab/evaluator/matcher.py#L76),
[SPEC §9](../../../SPEC.md#9-сопоставление-и-расчёт-награды).

| Тестовая ситуация | TP / FP / FN | Инспекции | F1 | Награда |
| --- | ---: | ---: | ---: | ---: |
| S01, пустой ответ | 0 / 0 / 0 | 0 | 1 | 1 |
| S01, одно ложное обвинение | 0 / 1 / 0 | 3 | 0 | −1 |
| S01, 30 ложных обвинений | 0 / 30 / 0 | 10 | 0 | −1 |
| S02, молчание | 0 / 0 / 1 | 4 | 0 | −1 |
| S02, один полный вывод | 1 / 0 / 0 | 4 / 5 | 1 | 0.992 / 0.990 |
| S02, тот же вывод дважды, включая перестановку ID и новый текст | 1 / 1 / 0 | 4 | 2/3 | 122/375 ≈ 0.325333 |
| S02, правильные сумма и ключи, чужая ссылка вместо обязательной | 0 / 1 / 1 | 4 | 0 | −1 |

Синтетическая альтернатива с полным допустимым набором принимается. Повтор
отдельной ссылки не заменяет отсутствующую. Неполные evidence, угаданный
affected ID, неверная валюта и сумма на одну единицу вне допуска проверены
отдельно. Структурные проверки покрывают 30/31 вывод, 10/11 ссылок,
1 000/1 001 символ, bool/float вместо целой суммы и несовпадающий episode ID.
Ошибочный truth, включая дубли одной причины, отклоняется до первого
наблюдения. Адресуемость и финансовая достаточность допустимых ссылок зависят
от отдельной проверки снимка. SPEC допускает ссылки из уже полученных
таблиц и документов без обязательного отдельного вызова на каждый ID.
[Тесты оценки](../../../../tests/evaluator/test_scoring.py),
[валидация truth](../../../../tests/evaluator/test_truth_validation.py).

Пройдена сознательная мутация оценщика в отдельной временной копии. На двух
копиях одного вывода S02 продукционный оценщик вернул P=0.5, R=1, F1=2/3,
reward=122/375. Тестовая копия с отключённой уникальностью вернула
TP/FP/FN=2/0/−1 и reward=1. Ручная проверка отклонила результат тестовой копии.
Исходник продукционного матчера сохранился.
[Контрольная мутация](../../../../tests/integration/test_evaluator_mutation.py).

## Два дополнительных сценария на открытом S01

1. **Отказ политики сохраняет финансовый балл в открытом API.** До первого
   действия доверенный драйвер фиксирует обычный ранний сбой адаптера через
   `abort`. Фактически `policy_failure`, `terminated=false`,
   `truncated=true`, доверенный `completed=false` и статус экспорта
   `failed`, при этом `step.reward=1.0` и `score.json.reward=1.0`.
   Причина в том, что `_finish` оценивает пустую сдачу, а S01 чистый.
   Внутренняя сводка уже исключает такие попытки из оцениваемых строк.
   Внешний потребитель награды может принять сбой за наилучший результат,
   если читает только скаляр. Это риск интеграции. Критерий приёмки отдельного
   изменения — клиент различает корректную пустую сдачу и отказ политики
   по контракту, отказ публикуется без действительного финансового балла,
   а добровольная пустая сдача и штатные усечения сохраняют общую формулу.
   [abort и финализация](../../../../auditlab/runner/env.py#L237),
   [сводка](../../../../auditlab/release/rehearsal.py#L341).
2. **Зафиксировано ограничение проверки времени.** С управляемыми часами
   валидный submit был принят в 0.9 с при лимите 1.0 с. Подставной доверенный
   оценщик продвинул часы до 1.4 с. Первое завершение осталось `submitted`,
   `terminated=true`, с одним вызовом оценки. Это соответствует проверке
   дедлайна до принятия действия в SPEC §8. Гарантию общего wall-clock от
   старта до финализации нужно подтверждать отдельно. Если организаторы
   требуют сквозной дедлайн, согласовать его начало и включить в приёмку
   задержку доверенного компонента, однократное `truncated_timeout` и
   измерение целевого выпуска с подготовкой и очисткой.
   [Проверка дедлайна](../../../../auditlab/runner/env.py#L207),
   [цикл выполнения](../../../../auditlab/runner/episode.py#L12).

Минимальные вызовы для этих двух наблюдений из корня репозитория
(`snapshot_dir` указывает на `fixtures/foundation/S01`):

```python
from auditlab.evaluator.service import handle
from auditlab.runner import make_env

snapshot = "fixtures/foundation/S01"
env = make_env("train")
try:
    env.reset(0, {"snapshot_dir": snapshot})
    print(env.abort("test adapter stopped before returning an action")[1:])
finally:
    env.close()

now = [0.0]

def evaluator(private_dir, submission, inspection_steps):
    now[0] += 0.5
    return handle({"private_dir": str(private_dir), "submission": submission,
                   "inspection_steps": inspection_steps})

env = make_env("closed", clock=lambda: now[0], evaluator=evaluator)
try:
    env.reset(0, {"snapshot_dir": snapshot, "time_limit_s": 1.0})
    now[0] = 0.9
    print(env.step({"action": "submit", "args": {"episode_id": "S01", "findings": []}})[1:])
    print(now[0])
finally:
    env.close()
```
