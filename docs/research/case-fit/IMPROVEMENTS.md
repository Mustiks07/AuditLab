# План усиления перед сдачей

Цель — представить проверяемую RL-среду по PDF, с одним комплектом исходников, архива и доказательств под точный SHA. Порядок учитывает цену отказа ядра и готовность отдельных владельцев. Оценки времени ниже инженерные, кроме отдельно обозначенного CI и ручной приёмки. [Матрица требований](REQUIREMENTS.md) · [Воспроизведения](evidence/README.md)

## P2 — после основной приёмки

- Обучение весов стоит исследовать только с заранее выделенным семейством для отложенной оценки и контрольной политикой. PDF не начисляет баллы за обучение само по себе. До сдачи такой эксперимент отнимает время у исправлений генерации и финализации.
- Новый UI, графики и массовая серия на 1 000 компаний полезны после стабильного архива. Для защиты уже есть проверяемая короткая история. Добавление названий и новых схемных полей до #22 создаёт лишний риск регрессии; текущий пробел разнообразия зафиксирован.
- Не превращаем внутренний F1, число тестов, частичную эвристику или максимальную награду oracle в оценку победы. Новые публичные результаты других команд сравнимы только при одинаковой версии правил, нагрузке и способе проверки. [Условия сравнения](COMPARISON.md)
