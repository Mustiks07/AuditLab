# Повтор Gemini на коде RC5 — 22 ноября 2026

**Итог:** реальные API-вызовы и независимый пересчёт выполнены. Полный протокол
повторения не завершён из-за ограничений сервиса; улучшение агента не проверялось.
Два завершённых ответа на исходную компанию с ошибкой не нашли нарушение,
один добавил ложный вывод. Отдельная диагностика без паузы клиента тоже пропустила
ошибку. Это измерение одной открытой dev-семьи, не оценка жюри и не holdout.

## Протокол и происхождение

Запуск использует заранее опубликованный
[replication-official.plan.json](../../agent-improvement-v2/replication-official.plan.json):
агент A-tools, `gemini-3.1-flash-lite`, reasoning `minimal`, максимум 4096 токенов
на ответ, 60 секунд от reset, 100 действий, пауза клиента 4 секунды.
Промпт A зафиксирован в [протоколе](../../agent-improvement-v2/protocol.json).
Его тождество историческому пилоту не утверждается: хеша промпта того пилота нет.

Предусмотрены четыре условия × три повтора: исходные чистая/ошибочная компании и
их варианты с преобразованными ID/порядком. Экономическая семья одна: публичный
набор `replication-922101`. Правильный незачтённый остаток — 3 024 000 минимальных
единиц KZT, то есть 30 240 ₸. Эпизоды уже лежат в репозитории; новые закрытые данные
не использовались. Между попытками промпт не менялся.

Исполненный checkout: `38448d386cb13c97872a7fc774371fbb8643c760`; его код совпадает
с RC5 `920b251ee3b1c12f9bc5ffe0eca3b5cb1bf8d78a`. Для облачного окружения пересобран
изолированный мост с этим кодом и доверенным CA; проверка TLS сохранена. Локальные
настройки прокси и image ID отличаются от переносимого рецепта. Хеш фактически
исполненного плана и ID образа сохранены в `receipt.json`; `portable.plan.json`
явно не выдаётся за побайтовую копию исполненного плана.

## Что получилось

| Условие | Попыток с повторами после сбоя | Submit | Тайм-аут | Ограничение темпа |
|---|---:|---:|---:|---:|
| Исходная чистая компания | 4 | 1 | 2 | 1 |
| Исходная компания с ошибкой | 7 | 2 | 0 | 5 |
| Преобразованная чистая | 0 | 0 | 0 | 0 |
| Преобразованная с ошибкой | 0 | 0 | 0 | 0 |
| Всего | 11 | 3 | 2 | 6 |

Из 12 предусмотренных слотов пять дали учитываемый исход (три submit и два
тайм-аута), один исчерпал повторы после сервисных сбоев, шесть не запускались.
Контроллер остановился с `consecutive_service_failures`: три сервисных сбоя подряд.
Все неудачные попытки сохранены. Три ограничения темпа возникли из-за паузы клиента,
ещё три попытки упёрлись в Retry-After провайдера; журнал содержит шесть ответов
HTTP 429 и два тайм-аута отдельных запросов. Суточная квота не объявлялась исчерпанной.

- Единственный завершённый ответ на чистой компании: пустой, корректный; 11 осмотров,
  return 0,978. Два других чистых исхода — тайм-ауты, а не успешные проверки аудитора.
- Первый завершённый ответ на компании с ошибкой: пустой; TP=0, FP=0, FN=1, return=-1.
- Второй: один несвязанный с эталоном вывод; TP=0, FP=1, FN=1, return=-1.
- По пяти учитываемым исходам: TP=0, FP=1, FN=2, micro F1=0. Средний return 0,1888
  включает два тайм-аута чистой компании, обработанных пустым ответом; он не доказывает
  успешное исследование этих компаний.
- Независимый скорер также показывает механическое применение официального правила
  ко всем 11 попыткам, включая сервисные сбои: средний return −0,2801818181818182.
  Это отдельная статистика; сбой API не считается доказательством ошибки рассуждения.

Заранее заданный критерий повторяемости на исходном **и преобразованном** условии
не проверен: преобразованные компании не были запущены. Интервал обобщения по одной
семье не строится. Сравнений A/B/C, улучшения от памяти или обучения весов здесь нет.

## Отдельная диагностика паузы клиента

После остановки основного запуска выполнена **одна дополнительная dev-попытка** на
исходной компании с ошибкой: тот же промпт A, модель и лимиты, но
`retry.min_interval_s=0`. Это исследовательская проверка причины, не часть исходного
протокола. Retry-After провайдера соблюдается; аккаунт не менялся.

Ответ завершён за **55,369 с**, 17 действий среды (16 осмотров и submit),
18 вызовов провайдера. Модель отправила пустой ответ: TP=0, FP=0, FN=1, return=-1.
Следовательно, данный пропуск нельзя объяснить только четырёхсекундной паузой.
Одна попытка не доказывает надёжность режима без паузы или качество модели в целом.
Стоимость обеих серий частично неизвестна из-за запросов без usage; `null` не заменён
нулём. Цены успешных запросов соответствуют заявленному пользователем Free Tier,
платёжный аккаунт не проверялся.

## Свидетельства и независимый повтор без API

В каждом каталоге сохранены `receipt.json`, `summary.json`, независимый `comparison.json`,
переносимый план, исходные записи всех попыток, наблюдения, промпты и журнал вызовов
провайдера. `independent/` содержит ответы для повторного расчёта отдельным скорером.
Ключа в этих файлах нет. Предварительные два сбоя локального запуска (права файлов
образа и устаревший адрес прокси) были до серии; финансового ответа не дали и в её
11 попыток не включены. Они не являются результатом модели.

Из корня checkout с зависимостями из `requirements.lock`:

```sh
python review/agent_generalization/run.py compare \
  docs/research/gemini/rc5-replication/replication-connected/independent
python review/agent_generalization/run.py compare \
  docs/research/gemini/rc5-replication/pacing-diagnostic/independent
```

Команды пересчитывают сохранённые ответы по публичной dev-паре и её эталонам,
не обращаются к API и не используют закрытый набор из 90 семейств.
Для новых сетевых запусков используйте переносимый план, подготовленный мост и ключ
только в окружении; каждый изменённый план требует отдельного каталога результата.
Повтор диагностического эксперимента не следует выдавать за исходную регистрацию.
