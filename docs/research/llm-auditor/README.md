## Агент

`LLMAuditor` (`agent.py`) реализует стык из CONTRACTS: `start(public_observation)`, `act(public_observation)
-> official_action`, `close()`.

- **Вход.** Модель получает только наблюдения официального адаптера: первое (`task`, `manifest`,
  `policy`, `remaining_steps`), затем `result`/`error`/`remaining_steps`.
- **Выбор действий.** Каждое действие и момент `submit` выбирает модель: tool use, один вызов за ответ
  (`disable_parallel_tool_use`). Контроллер сам вызывает `step`, следующий `act` получает настоящий ответ среды.
- **Вариант `memory`.** Добавлены локальные инструменты `note` и `update_note`: факты со ссылками,
  открытые вопросы, гипотезы со статусом `open`/`confirmed`/`rejected`. Действий среды они не тратят,
  но тратят время и токены. Состояние заметок показывается модели после каждого ответа среды. Ссылка
  на ещё не прочитанную запись помечается как `UNSEEN`.
- **Арифметика** — только через разрешённый `calculator`; это требование стоит в промпте.
- **Проверка перед submit** одинакова в обоих вариантах. Она смотрит только формат и ссылки: лимиты
  30/10/1000, `episode_id`, документированный `type`, целую сумму, доказательства, уже прочитанные в этом
  эпизоде. Проблемы возвращаются модели ошибкой инструмента без траты действия, не больше двух раз.
  Затем отправляется то, что решила модель. Финансовое значение проверка не подставляет и не исправляет
  (есть регрессия).
- **Сбои модели.** Без вызова инструмента модель получает до двух напоминаний, потом попытка
  `invalid_response`. Отказ даёт `provider_refusal`. Неизвестный инструмент уходит в среду как
  `unknown_action` и тратит шаг.
- **Версии.** `AGENT_VERSION` 1.0, `PROMPT_VERSION` `llm-auditor-prompt-1.0`. `prompt_hash` — SHA-256
  системного промпта, инструментов, параметров провайдера и `max_tokens`.

## Провайдер Claude

`AnthropicProvider` (`providers.py`) работает через официальный Python SDK `anthropic`, клиент `Anthropic()`.

- **Модель и мышление.** Модель по умолчанию `claude-opus-5-5`. Thinking адаптивный (умолчание модели,
  не отключается), задаётся только `output_config.effort` (по умолчанию `high`). Ответ ассистента
  возвращается в историю без изменений, поэтому блоки thinking остаются действительными.
- **Кэш.** `cache_control` на верхнем уровне: автоматическое кэширование растущего префикса.
- **Повторы.** Собственные повторы SDK выключены (`max_retries=0`). Все повторы делает и оплачивает
  `reliability.py`.
- **Fallback.** Серверный fallback при отказе (`fallbacks`) **по умолчанию выключен** в конфигурациях
  эксперимента. Ответ другой модели смешал бы серии. Если его включить, попытка помечается
  `served_by_fallback` и записывается фактическая `model_served`.
- **Обучение.** Fine-tuning моделей Claude на Claude Platform нет: в перечне возможностей
  (platform.claude.com/docs/en/build-with-claude/overview, проверено 21.11.2026) его нет. Поэтому серия
  обучения идёт на отдельной обучаемой модели.

## Надёжное исполнение

Каждая логическая попытка вызова модели ограничена:

- **Повторы:** до 4 на вызов, только для `rate_limit`, `timeout`, `server`, `connection`; пауза
  экспоненциальная с джиттером или по `Retry-After`.
- **Срок:** ни ожидание, ни запрос не выходят за дедлайн попытки. Дедлайн задаёт контроллер из
  `env.seconds_left()`, поэтому в официальном протоколе 60 с включают задержки API и повторы.
- **Бюджет:** перед каждым запросом худшая оценка стоимости (входные токены без кэша ×1,25 + `max_tokens`)
  сравнивается с бюджетом попытки. Модель без цены с бюджетом вызвать нельзя.
- **Учёт:** каждая проба записывается в `provider_calls.jsonl`: хеш запроса, usage, стоимость, задержка,
  ошибка, фактическая модель. Неудачные пробы остаются в стоимости и отчёте.

| Протокол | Срок | Действий | Мост |
|---|---|---|---|
| `genesis-official-60s` | 60 с от reset, включая API и повторы | 100 | только изолированный (Docker) |
| `auditlab-research-600s` | 600 с | 100 | любой; результат никогда не называется официальным |

**Статусы попыток:** `completed`, `action_budget_exhausted`, `timeout`, `provider_error`,
`provider_refusal`, `invalid_response`, `budget_stop`, `bridge_failure`, `interrupted`.

**Финансовый результат** (`official`) выставляется только для первых трёх; для остальных — `null` с причиной.
Отдельное поле `official_by_rule` хранит то, как среда оценила попытку по официальному правилу (пустые
findings при сбое). По протоколу Claude Pro 2 средняя награда считается по всем попыткам.

**Resume** (`run_experiment`):

- завершённая попытка повторно не запускается и не оплачивается;
- прерванная (`attempts/<id>.partial`) сохраняется со всеми оплаченными вызовами как `interrupted`,
  а слот повторяется под новым `attempt_id` (`--retry1`);
- изменённый план в тот же каталог не пускается.

## Изоляция и секрет

- **Мост.** Модель работает в отдельном процессе `python -m auditlab.research.agents.bridge`. Он
  получает только публичные наблюдения и настройки (JSON Lines) и не импортирует evaluator, runner,
  generator, environment, verifier, release (есть регрессия). Путей, seed и truth он не получает; файлы
  пишет только доверенный контроллер.
- **Docker-топология** (`sandbox.py`, `docker/bridge/`):
  - контейнер моста подключён к `--internal`-сети без шлюза; `--read-only`, `--cap-drop ALL`, без томов;
  - единственный выход наружу — контейнер `egress_proxy`. Он пропускает только `CONNECT` на
    перечисленные `host:443` (по умолчанию `api.anthropic.com:443`) и не пускает имя, которое
    разрешается в частный адрес.
- **Ключ** передаётся только через окружение по имени из конфигурации (`api_key_env`), в Docker как
  `-e NAME` без значения в argv. В коде, логах, артефактах, планах и UI его нет; в тестах значение-маркер
  ищется во всех argv и файлах.
- **Инструменты агента** — пять официальных действий и локальные заметки. Shell, файлов и
  произвольной сети у модели нет.
- **Dev-подпроцесс** (`transport=subprocess`) — не сетевая песочница, официальный протокол его не допускает.

## Артефакты попытки

```
<out>/attempts/<attempt_id>/attempt.json      протокол, эпизод (sha256 public), агент, модель, параметры, prompt_hash,
                                              статус, final_answer, inspection_steps, токены, стоимость, время, source_sha
                           prompt.json        системный промпт и инструменты
                           steps.jsonl        каждое официальное действие и наблюдение
                           transcript.jsonl   публичный диалог с моделью (без скрытого thinking)
                           provider_calls.jsonl  каждая проба API
                           memory.json        заметки (вариант memory)
<out>/trusted/<attempt_id>/evaluation.json    закрытая оценка: official, official_by_rule, matches, unmatched
<out>/run_manifest.json, summary.json         план и его sha256; внутренняя сводка со знаменателями
```

`export-review` пишет тот же прогон в формате `compare_experiment` Claude Pro 2 (`agent-generalization-1.1`):
`experiment.json` и `attempts/*.json`. Финальный пересчёт, интервалы по семействам и holdout принадлежат
его протоколу. Мой `summary.json` — внутренняя бухгалтерия.

## Обучение весов

1. **Учитель.** `training/demonstrations.py` на доверенной стороне строит по эталону короткие верные
   траектории через тот же агент и исполнитель. Только разделы `train`/`curriculum`/`search`, стоимость 0.
   Попытки помечены `agent.kind = oracle_demonstration` и никогда не являются результатом агента. Такой
   учитель не требует сторонней модели, поэтому ветви «случайный набор» и «адаптивный набор» различаются
   только выбором эпизодов.
2. **Набор.** `python -m auditlab.research.training build-sft` превращает транскрипты в чат-примеры с
   инструментами. Защиты: разделы, `test_double`, порог награды, источник учителя. Транскрипты сторонней
   модели (например, Claude для обучения не-Claude модели) запрещены без явного `teacher_terms_acknowledged`.
   `equalize` уравнивает ветви по числу примеров и оценке токенов.
3. **Обучение.** `train --config --curriculum --out [--dry-run]`:
   - dry-run, предпроверка и оценка бюджета;
   - платное или GPU-задание стартует только при цене, бюджете, ключе или GPU и `confirm_paid`;
   - id файла и задания записываются до продолжения, resume опрашивает то же задание и не создаёт второе;
   - `training.json` содержит `kind="weights"`, `job_id`, `checkpoint_id`, `result_model`, `mock`, `status`.
   Prompt, память и few-shot этим путём не оформляются и обучением весов не называются.
4. **Backend обучения:**
   - `local_lora` — LoRA SFT открытой модели через Hugging Face TRL на отдельной GPU-машине (профиль
     gpu-training, не 4-гигабайтная поставка). Обученный адаптер подаётся через OpenAI-совместимый
     сервер vLLM и оценивается тем же агентом (`provider: openai_compatible`);
   - `openai_compatible` — API fine-tuning OpenAI. По странице deprecations (проверено 21.11.2026) с
     02.07.2026 задания могут создавать только организации, у которых за последние 60 дней был inference
     на дообученной модели, а 06.01.2027 создание прекращается для всех. Для нашей команды этот путь,
     вероятно, закрыт.
5. **Переоценка.** Сравнение `T0`, `T_random`, `T_adaptive` — один план с одной исходной моделью и
   одинаковыми настройками. Результаты серии Claude и обучаемой серии не смешиваются.

## Настоящие артефакты (`evidence/`, код `9a9790a`)

Пересоздаются командой `bash docs/research/llm-auditor/make_artifacts.sh [checkout review/agent-generalization]`:
сеть не нужна, платных вызовов нет.

**`2026-11-21-baselines-open-dev`.** Прогон базовых политик на 10 опубликованных dev-эпизодах по
официальным лимитам. Через официальный адаптер прошло 40 попыток, все `completed`. Затем `export-review`
и независимый пересчёт скорером Claude Pro 2 (`independent-compare.json`, ветка `review/agent-generalization`
`079bd8c`). Пересчёт совпал с моей сводкой по TP/FP/FN, средней награде и FP на чистых:

| Политика | micro F1 (TP/FP/FN) | средняя награда | чистые с обвинением |
|---|---|---|---|
| reconcile | 1,0 (11/0/0) | 0,982 | 0 из 2 |
| empty | 0 (0/0/11) | −0,600 | 0 из 2 |
| random, seed 1 | 0 (0/0/11) | −0,602 | 0 из 2 |
| flag_all | 0 (0/300/11) | −1,000 | 2 из 2 |

Разница по семействам у Claude Pro 2: reconcile − empty = 1,582 (95% [0,982; 1,982]); random − empty — не
показана. Это проверка конвейера на открытых данных. Не официальный балл и не модельный эксперимент
(`live=false`).

**`2026-11-21-e1-dry-run`.** План E1: 10 эпизодов × 2 ветви × 3 повтора, 60 платных попыток.
- `dry-run` перечисляет недостающие условия.
- Платный запуск отклонён до создания каталога: нет лимита и ключа.
- `preflight` и `smoke` возвращают `not_checked` с 0 сетевых вызовов.

**`2026-11-21-training-dry-run`.** Путь обучения весов на 10 опубликованных train-эпизодах:
1. Демонстрации: 10 попыток `oracle_demonstration`.
2. `build-sft`: 10 примеров, около 55 тыс. токенов (оценка), источник учителя только демонстрации.
3. `train --dry-run`: около 110 тыс. токенов на 2 эпохи.
4. Реальный `train`: `not_started_missing_access`. Нет `torch`, `transformers`, `peft`, `trl` и CUDA-GPU,
   базовая модель — заглушка до решения интегратора.

`curriculum.json` здесь — весь опубликованный train, а не ветвь random или adaptive.


## Что нужно от интегратора для живых запусков

1. **Провайдер и модель.** Подтвердить Anthropic API и `claude-opus-5-5` (или другую модель из
   `pricing.py`) и сверить цены со страницей pricing. Сейчас цены взяты из справочника, кэшированного
   03.11.2026.
2. **Ключ.** Положить его в переменную окружения контроллера (`ANTHROPIC_API_KEY` или имя из конфига)
   через механизм секретов CI или хоста. Не в чат и не в файлы.
3. **Лимит расходов.** Задать `budget.max_usd_total` и `max_usd_per_attempt` в плане. Ориентир по
   протоколу Claude Pro 2: 1200 попыток E1 × 120–240 тыс. входных токенов.
4. **Мост.**
   - Закрепить версию `anthropic` в `docker/bridge/requirements.in`, собрать lock командой из TEAM.md
     и wheels, затем собрать и загрузить образ `auditlab-bridge`.
   - Проверить Docker-топологию на хосте.
   - Без этого допустим только исследовательский протокол через dev-подпроцесс.
5. **Обучение.**
   - Машина с CUDA-GPU и закреплёнными `torch`/`transformers`/`peft`/`trl` (`docker/train-gpu/requirements.in`).
   - Выбранная открытая модель (id или путь), бюджет GPU-часов и место на диске.
   - Для OpenAI — только при подтверждённом доступе организации к созданию заданий.
6. **Выборки.** Финальный holdout и семейства dev даёт Claude Pro 2; curriculum ветвей random и
   adaptive даёт GPT Pro 1.

Пока пункты 1–4 не выполнены, `smoke` возвращает `not_checked` без сетевых вызовов. Пока не выполнен
пункт 5, обучение возвращает `not_started_missing_access` с перечнем условий.
