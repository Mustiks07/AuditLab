# Протокол независимой проверки v2 (Claude Pro 2, #43)

`protocol_id`: `independent-assurance-2.0`. База: `main` `988a5dbb46886d88d811e059965d893dd9fef6f7`
(генератор 1.7, профиль 1.1). Протокол записан и опубликован **до** любых результатов этой
итерации: до прогона решателя, метаморфных проверок, mutation testing и пересчёта экспериментов.
Он продолжает `agent-generalization-1.1` ([PROTOCOL.md](../agent-generalization/PROTOCOL.md)).
Решения о статистике и выводах из 1.1 остаются в силе, если ниже не сказано иное.

Статусы любой проверки: `passed`, `failed`, `not_checked`. Неподдержанный случай получает
`not_checked` с причиной и никогда не засчитывается как `passed`.

## 1. Паспорт корректности

Паспорт — расширение существующего `validate_candidate`, а не новая система. Он привязан к
точному снимку: SHA-256 каждого файла `public/` и `private/`, SHA кода, `protocol_id`.
`verify_passport(passport, episode)` пересчитывает хеши; любое отличие даёт `failed`.

| Проверка | Что утверждает | Источник ответа |
|---|---|---|
| P1 `formats` | форматы раздела 03 | файлы |
| P2 `source_book_consistent` | полная исходная книга до мутации согласована: журналы сбалансированы, мой расчёт не находит ошибок и противоречий | мой калькулятор |
| P3 `mutation_explained` | каждое отличие исходной книги от итоговой перечислено в `source_transition`, и наоборот | построчное сравнение |
| P4 `mutation_declared` | реальное изменение соответствует заявленной в provenance мутации: тип, объекты, сумма | мой ответ против `provenance.mutations`, после фиксации ответа |
| P5 `independent_answer` | мой ответ и арифметика по `public/`, хеш записан до чтения truth | мой калькулятор |
| P6 `answer_matches_truth` | мой ответ совпадает с эталоном по типу, объектам, сумме, валюте; доказательства покрывают набор | после фиксации |
| P7 `evidence_reachable_within_budget` | ключи эталонных доказательств обнаруживаются листингами по курсорам в пределах 100 действий и 60 с | **submit строится из truth; это не решение** |
| P8 `independent_solver` | ответ, построенный только по наблюдениям публичного адаптера, верен | см. раздел 2 |
| P9 `matched_clean_control` | чистая пара: та же коммерческая история, без находок, без признака варианта | пара снимков |
| P10 `reproducible_generation` | повторная генерация по `seed` и `config` из provenance даёт байт-в-байт те же файлы | генератор как чёрный ящик |
| P11 `snapshot_binding` | паспорт относится именно к этому снимку | хеши |

P7 и P8 — разные утверждения. P7 доказывает только доступность и бюджет. Самостоятельную
разрешимость доказывает только P8.

## 2. Независимый решатель (P8)

- Получает данные **только** через `judge_adapter`: `reset`, затем `list_records` по курсорам
  с `limit` = максимум страницы. Путь к снимку решателю не передаётся; файлы он не открывает.
- Из наблюдений восстанавливает таблицы и запускает мой калькулятор на восстановленных данных.
  Доказательства берутся только из ключей, которые решатель сам наблюдал.
- Ответ записывается с SHA-256 **до** submit и до чтения truth. Затем submit через адаптер,
  оценка адаптером (официальные правила) и моим эталонным scorer. Только после этого контроллер
  открывает truth.
- Лимиты Genesis: 100 действий вместе с submit, 60 с от reset.
- `not_checked`, а не `passed`: листинг не помещается в бюджет; калькулятор сообщает о
  немоделируемой ситуации (`allocation_instructions`, неоднозначный FX-источник, несколько ссылок);
  адаптер недоступен.
- Отрицательные контроли: решатель на чистой паре (ожидается пустой ответ), решатель при
  испорченной таблице (ожидается отказ, а не «passed»), решатель с урезанным бюджетом
  (ожидается `not_checked`).

## 3. Новые семейства GPT Pro 1 и метаморфные отношения

Страты (публичные dev-seed `9220001`…, не закрытые): несколько траншей (`split_payment`,
частичный зачёт), разные доли (частичный и полный пропуск, моё изменение доли), возвраты
(`refund`), границы периода (`settlement_timing` before/at/after, `period_cutoff`), валюты
(KZT, USD, JPY с экспонентой 0, KWD с экспонентой 3), взаимодействия
(`allocation_fx_same_payment`, `cutoff_fx`, две ошибки разных типов), похожие законные операции
(`equal_amount_different_supplier`, `archive_copy`, `next_day_settlement`). Также проверяются
заявленные ожидания `auditlab.research.curriculum.families.boundary_variants` (#49).

Преобразования выполняет **мой код** на публичных файлах (и согласованно на truth, где нужен
эталон), а генератор — только там, где сказано «генератор».

| Отношение | Преобразование | Ожидание |
|---|---|---|
| MR1 переименование | моя перестановка всех ID и порядка строк; отдельно — `renamed_snapshot` GPT Pro 1 | ответ равен исходному с точностью до отображения ID |
| MR2 законный отвлекающий документ | моя вставка архивной копии счёта и счёта той же суммы другому контрагенту; генератор с добавленным `refund` | тип, сумма, валюта и объекты находок не меняются |
| MR3 исправление | мой зачёт остатка до границы, удаление повторного признания, исправление FX-оценки, перенос признания в период | соответствующая находка исчезает |
| MR4 изменение суммы | моё изменение суммы зачёта на Δ | сумма находки меняется ровно на Δ; старый ответ теперь неверен |
| MR5 две ошибки | исправление одной из двух ошибок разных типов | вторая находка не меняется |

Для каждого отношения проверяются решатель и официальный scorer на преобразованном эталоне
(старый ответ на новом снимке должен давать FP/FN там, где смысл изменился).

## 4. Закрытые семейства и раздел по экономическому происхождению

- Семья = экономическое происхождение: каноническая история чистой исходной книги без ID и
  порядка (`canonical.whole_history`). Все потомки — переименованные, сокращённые,
  исправленные и иначе преобразованные варианты — наследуют раздел корня
  (`lineage.assign`). `lineage.check` отклоняет набор, где потомок оказался в другом разделе
  или где каноническая история повторяется между разделами.
- Закрытая выборка v2 = 78 семейств v1 (обязательство `dcd56b93…bc65`, пересобираются из
  запечатанных seed с проверкой хешей) + 12 слотов полного пропуска на генераторе 1.7.
  10 пограничных слотов остаются `not_checked`, если дефект D3 не исправлен.
- В PR публикуются протокол, схема, сводка покрытия и хеши. Документы, seed, ID и ответы не
  публикуются до заморозки вариантов агента; закрытый запуск согласуется через интегратора.
- Статус выборки ведётся в `sealed-status.json`: `sealed` → `used_once` после первого
  финального запуска → `no_longer_sealed` при любом повторном использовании или раскрытии.

## 5. Mutation testing оценщика

Мутации применяются к **копии** `auditlab/evaluator` во временном каталоге; рабочий оценщик
не меняется (проверяется `git diff --exit-code -- auditlab`). Операторы:

| ID | Намеренный дефект |
|---|---|
| M1 | не проверяется валюта |
| M2 | не проверяется сумма |
| M3 | допуск суммы на 1 больше |
| M4 | не проверяются объекты |
| M5 | не проверяется тип |
| M6 | объекты сравниваются с учётом порядка |
| M7 | не проверяется покрытие набора доказательств |
| M8 | не проверяется доступность ссылок |
| M9 | повторные выводы засчитываются как TP |
| M10 | жадное сопоставление вместо максимального |
| M11 | пустой ответ на чистой компании даёт F1 = 0 |
| M12 | нет штрафа за инспекции |
| M13 | нет ограничения награды снизу |
| M14 | не проверяется `episode_id` ответа |

Набор тестов: автоматические комбинации неправильных ответов на настоящих эталонах генератора 1.7
(смена валюты, сумма ±1 и ±допуск, недостающее и недоступное доказательство, лишнее доступное
доказательство, перестановка и потеря объекта, неверный тип, повтор вывода, лишний вывод,
пустой ответ, пары возмущений на двух ошибках). Ожидаемый результат каждого случая считает мой
эталонный scorer (`review/genesis_acceptance/reference.py`). Мутант **обнаружен**, если хотя бы
один случай даёт иной `tp/fp/fn/reward` или иное сопоставление. Выжившие разбираются вручную;
мутант признаётся **эквивалентным** только с доказательством (рассуждение плюс исчерпывающая
проверка на малом домене) и считается отдельно. Отдельно фиксируется, какие мутанты ловят
собственные тесты проекта `tests/evaluator`.

## 6. Пересчёт эксперимента Claude Pro 1

Источники: живой пилот Gemini (`docs/research/gemini/evidence`, main), прогон базовых политик
(`docs/research/llm-auditor/evidence/2026-11-21-baselines-open-dev`, main), набор повторения
PR #52 на его head, если он доступен.

- Единица обобщения — экономическая семья (каноническая история исходной книги). Повторы,
  переименованные и переставленные копии одной семьи сворачиваются в одно значение семьи.
- Отдельно: завершение, ошибки сервиса (429, квота, транспорт), качество на чистых компаниях,
  верность суммы, валюты, объектов и доказательств каждого вывода, парные результаты по семьям.
- Интервал и p-value — только при ≥ 2 семьях; вывод об улучшении — только при ≥ 10 семьях и
  интервале, не содержащем 0. Одна семья или отобранные попытки не дают вывода об улучшении.
- Попытка без ответа из-за сервиса не превращается в «пропуск ошибки моделью» и не исчезает из
  знаменателя: она показывается отдельно в обоих разрезах.

## 7. Что считается результатом

Воспроизводимые проверки с положительными и отрицательными контролями, ответы с хешами до truth,
отчёт с контрпримерами (SHA, вход, команда, ожидаемое и фактическое) и ограничениями. Отсутствие
дефектов — допустимый результат.
