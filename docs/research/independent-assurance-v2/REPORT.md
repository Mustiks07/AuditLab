## 2. Разрешимость: свидетель и решатель разделены

- **Свидетель** (`witness_trajectory`, P7) по-прежнему строит submit из truth. Теперь он явно помечен: `claim = evidence_reachable_within_budget`, `is_independent_solution = false`, `submit_built_from = truth`. Он доказывает только то, что эталонные доказательства достижимы листингами в пределах 100 действий и 60 с.
- **Решатель** (`solver.py`, P8) работает иначе:
  - получает только функцию `step` и первое наблюдение адаптера, путь к снимку ему не передаётся;
  - листает таблицы по курсорам и восстанавливает их из наблюдений;
  - считает ответ моим калькулятором и берёт только наблюдённые ключи доказательств;
  - фиксирует SHA-256 ответа до submit;
  - после submit ответ оценивает официальный адаптер и мой scorer. Только затем контроллер открывает truth.
- `not_checked` вместо `passed` получают:
  - бюджет, которого не хватает на листинг;
  - ситуация, которую калькулятор не моделирует (`allocation_instructions`, неоднозначный FX);
  - больше 10 доказательств у одного вывода.
- Отрицательные контроли (тесты):
  - решатель с бюджетом 4 действия → `not_checked`;
  - скрытый платёжный документ → не `passed`;
  - чистая пара → пустой ответ, `passed`.
- Официальный адаптер и мой scorer совпали на каждом запуске решателя.

Наблюдение для GPT Pro 1 и Claude Pro 3 (их код я не менял): `auditlab/research/curriculum/validation.py` закрепляет мой прежний SHA `079bd8c` и пишет «public witness passed» как основание разрешимости. Для утверждения о самостоятельном решении нужно требовать `independent_solver`. При обновлении закреплённого SHA учтите: у производных снимков (переименованных, сокращённых, исходных книг) P4 и P10 теперь `not_checked`, поэтому общий статус будет `not_checked`. Допустимость такого варианта проверяет `families.acceptable`.

## Ограничения

- Новых живых запусков модели нет. Набор Gemini — одна семья и одна завершённая попытка: ни интервала, ни вывода о модели.
- Калькулятор решателя — тот же, что в моём независимом ответе. Решатель доказывает разрешимость по данным, полученным только через адаптер. Он не доказывает, что мой калькулятор верен там, где эталона нет; это закрывают P6 и метаморфные отношения.
- Метаморфные преобразования покрывают распределение, FX, дубликат и откат любых мутаций. Собственного исправления cutoff нет — его закрывает откат по `source_transition`.
- Операционализация семьи для снимков без исходной книги: общие ≥ 50% коммерческих цепочек. Это правило выбрано после протокола; при нём объединена ровно одна пара (C2).
- Mutation testing: мой набор не содержит граничных случаев лимитов (Y4–Y6). Их ловят тесты проекта.
- `tests/research_integration` на Windows: `test_symlink_cannot_publish_private_artifact` требует права на symlink. Без `PYTHONUTF8=1` один тест падает на cp1251. С UTF-8 тест сравнения и консоли проходит.
