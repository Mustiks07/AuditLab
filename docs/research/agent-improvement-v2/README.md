### 1. Квоты и возобновление

В пилоте Gemini три из четырёх попыток закончились HTTP 429, и каждая сразу завершала попытку. Теперь:

- **Разбор 429.** Из тела ответа Google берутся `RetryInfo.retryDelay` и `QuotaFailure.quotaId`.
  Поминутный лимит — `rate_limit`: повтор после `Retry-After`. Суточная квота — `quota_exhausted`:
  внутри попытки не повторяется.
- **429 у дедлайна.** Если ожидание не помещается до конца попытки, исход остаётся `rate_limited`.
  Раньше это превращалось в таймаут, который официальное правило засчитывает как пустой ответ модели.
  HTTP 429 не бывает пропуском, ложным обвинением или таймаутом модели.
- **Темп запросов.** Необязательная пауза между запросами (`retry.min_interval_s`) под лимит
  бесплатного тарифа.
- **Статусы попыток** `rate_limited` и `quota_exhausted`. Вместе с `provider_error`, `bridge_failure`,
  `interrupted` и `budget_stop` это **исходы сервиса**: они есть во всех знаменателях, но не
  засчитываются модели. Для независимого скорера Claude Pro 2 они экспортируются как `provider_error`.
- **Повтор слота после сбоя сервиса.** Новый `attempt_id` и пауза `max(cooldown_s, Retry-After)`, не
  более `max_slot_retries` раз; все неудачные попытки остаются в отчёте.
- **Остановка запуска с понятной причиной:**
  - `provider_quota_exhausted` — исчерпана квота;
  - `consecutive_service_failures` — N сбоев сервиса подряд;
  - `spend_limit`;
  - `stop_requested`;
  - `plan_finished`.

  Каждый запуск дописывается в `run_manifest.json` (`invocations`). Завершённые слоты повторно не
  запускаются и не оплачиваются. Слот с исчерпанной квотой повторяется только при следующем запуске,
  после сброса квоты.

Смена аккаунтов для обхода лимитов не поддерживается и не планируется.

### 2. Замороженный набор повторения

[`replication-922101/`](replication-922101/replication-set.json): та же dev-семья, что в пилоте (seed
922101, частичное распределение, эталон 3 024 000 мин. ед. KZT = 30 240 ₸), четыре условия.

| Условие | Что это | Независимая проверка (Claude Pro 2) |
|---|---|---|
| `original_error` | снимок генератора пилота | passed, 7/7 проверок |
| `corrected_clean` | та же история без дефекта: согласованная по размеру исходная книга, пустой эталон | passed, 7/7 |
| `transformed_error` | исходное нарушение: переименованы документы, переставлены строки | not_checked: 5 passed, исходной книги у копии нет по построению |
| `transformed_clean` | то же для чистой компании | not_checked: 5 passed, то же |

Все файлы заморожены по sha256 (`python -m auditlab.research.agents.replication check --out …`).
Набор принадлежит dev и никогда не используется как holdout.

**Проверка самого набора** (бесплатно, локальные политики, официальные лимиты,
[`evidence/baselines`](evidence/baselines-independent-compare.json)). Пересчёт скорером Claude Pro 2
совпал с моей сводкой:

| Политика | TP/FP/FN | средняя награда | чистые с обвинением |
|---|---|---|---|
| reconcile | 2/0/0 | 0,988 | 0 из 2 |
| empty | 0/0/2 | 0,000 | 0 из 2 |
| flag_all | 0/120/2 | −1,000 | 2 из 2 |

Документальная сверка находит ошибку и в исходном, и в преобразованном нарушении и не обвиняет чистые
компании. Значит, набор разрешим по публичным данным и различает ошибку и её отсутствие. Это проверка
набора, а не замер модели.

**План повторения** — `replication-official.plan.json`: агент A с теми же моделью и настройками, что в
пилоте, 4 условия × 3 попытки, 60 с. Отдельно — `replication-research.plan.json` на 600 с, где темп
запросов и квоты не превращаются в нехватку времени. Пропуск назовём повторяемым, только если на каждом
ошибочном условии он есть хотя бы в 2 из 3 **завершённых** попыток. Знаменатель включает
незавершённые попытки. Сейчас это **не проверено**: `evidence/replication-live.refused.json` —
запуск отклонён до каких-либо запросов, `GEMINI_API_KEY` не задан.

### 3. Протокол A/B/C — зафиксирован до результатов

[`protocol.json`](protocol.json) хранит хеши планов и промптов.

- **A** — исходный агент.
- **B** — A и общий метод аудита. Написан без обращения к слабостям, траекториям и эталонам AuditLab.
- **C** — A, процедура проверки целевых платежей и один рабочий пример. Источники:
  - наблюдённые слабости: пропуск в пилоте Gemini и пропуски распределения у случайной политики в
    curriculum GPT Pro 1;
  - правило — из публичного текста `policy.allocation`;
  - пример — из **train**-компании `E39A14EA…`.

  Значений dev-семьи 922101 в C нет (тест).
- **Одинаково для всех вариантов:** модель, параметры, инструменты, лимиты, бюджеты, вариант без памяти.
  Добавки B и C отличаются по длине не более чем на 10% символов (тест). Токены учитываются по каждому
  вызову.
- **Хеш A** совпадает с хешем исходного агента. Сверить его с пилотом напрямую нельзя: в экспорте
  пилота хеш промпта не сохранён.
- **Настройка** — только на train и dev (`abc-dev.plan.json`). До фиксации настройка с живой моделью
  невозможна (нет ключа), поэтому промпты — первые версии.
- **Финал:** запечатанный holdout Claude Pro 2 через интегратора, один раз
  (`abc-final.plan.template.json`).
- **Основная метрика** — средний return по семьям; парные разности B−A, C−A и C−B, кластерный
  bootstrap Claude Pro 2.
- **Решение.** Улучшение показано, только если 95% интервал исключает 0 и не растёт доля чистых
  компаний с обвинением. Нулевые и отрицательные результаты публикуются.

Изменение промпта и пример не являются обучением весов.

### 4. Метрики

Сводка (`summary.json`) по каждой ветви:

- micro F1 и распределения награды;
- **исходы сервиса** по статусам;
- **содержательные исходы**: попытки на ошибочных компаниях с пропуском, пропущенные ошибки по типу,
  чистые компании с ложным обвинением;
- метка каждого вывода (`correct`, `wrong_amount`, `wrong_currency`, `wrong_entities`,
  `evidence_incomplete`, `evidence_unavailable`, `duplicate`, `false_accusation_on_clean`,
  `unrelated_claim`);
- завершение, действия, время, токены, стоимость.

Диагностика строится на доверенной стороне и агенту не передаётся.

### 5. Обучение весов

[`evidence/hardware-probe.json`](evidence/hardware-probe.json): AMD Ryzen 5 7520U, 8 потоков, 15,3 ГБ
RAM, встроенная AMD Radeon. Обучение весов здесь **невозможно**:

- нет NVIDIA GPU и CUDA (бэкенду `local_lora` нужна CUDA, ориентир — от 16 ГБ видеопамяти для модели
  класса 7B);
- не установлены `torch`, `transformers`, `peft`, `trl`;
- нет `vllm` для повторной оценки.

Пакеты не ставились и ничего не скачивалось.

Исполнение подготовлено ([`run_e3_gpu.sh`](run_e3_gpu.sh), [`e3-training.plan.template.json`](e3-training.plan.template.json)):

1. **Проверка машины:** `probe-hardware`, при блокерах сценарий останавливается.
2. **Наборы и обучение:**
   - два curriculum GPT Pro 1 (uniform и adaptive);
   - демонстрации по эталону только на train;
   - SFT и уравнивание по числу примеров и токенам;
   - два LoRA-задания с одинаковыми настройками; resume без дубликатов.
3. **Оценка:** vLLM обслуживает базовую модель и оба адаптера; сравниваются T0, T_random и T_adaptive
   тем же агентом A.

Ни few-shot, ни память, ни промпт обучением весов не называются.

  - проверка замороженного набора (12 попыток, независимый пересчёт совпал);
  - dry-run всех живых планов;
  - отказ живого запуска без ключа (0 запросов).
- **Ранее, интегратором** (не в этой работе): одна завершённая попытка Gemini 3.1 Flash-Lite пропустила
  ошибку 30 240 ₸, три попытки — HTTP 429 (`docs/research/gemini`).

## Что не подтверждено

- **Повторяемость пропуска Gemini:** одно наблюдение, повторение подготовлено, не выполнено.
- **Эффект B и C относительно A:** нет живых запусков, нет dev-настройки, нет holdout.
- **Эффект обучения весов:** нет GPU.
- **Совпадение A с промптом пилота:** хеш пилота не сохранён.

## Что заблокировано и что нужно

1. **Живые прогоны.** Ключ `GEMINI_API_KEY` в окружении контроллера (не в файлах и не в чате), собранный
   образ моста `auditlab-llm-bridge:gemini` и проверка тарифа, затем:
   `python -m auditlab.research.agents run --plan docs/research/agent-improvement-v2/replication-official.plan.json --out artifacts/v2-replication --confirm-paid`.
   При исчерпанной квоте запуск остановится с причиной; повторить ту же команду после сброса.
2. **dev A/B/C.** То же с `abc-dev.plan.json`: 108 попыток; на бесплатном тарифе возможны несколько
   суточных квот.
3. **Финал.** Claude Pro 2 предоставляет эпизоды holdout, интегратор заполняет `abc-final.plan.template.json`
   и запускает один раз.
4. **E3.** CUDA-машина с 16 ГБ+, закреплённые пакеты `docker/train-gpu`, выбранная открытая модель,
   два curriculum GPT Pro 1, затем `run_e3_gpu.sh`.
