# Живой A/B/C: проверка доступности сервиса, 22 ноября 2026

**Сравнение качества не получено.** На одном открытом dev-эпизоде ни A, ни B, ни C
не отправили ответ. В режиме 60 секунд все три попытки остановились на минутной квоте
Gemini. В отдельном исследовательском режиме 600 секунд все три достигли тайм-аута.
Остальные слоты не запускались. Это неполная проверка работоспособности, не результат
полного бенчмарка, не доказательство преимущества C и не балл жюри.

## Что было зафиксировано

[A/B/C и их происхождение](protocol.json) не менялись по промежуточным финансовым
результатам. Модель — `gemini-3.1-flash-lite`, reasoning `minimal`, максимум 4096
выходных токенов на вызов. План: 12 открытых dev-эпизодов × 3 повторения × 3 варианта
= 108 слотов для каждого режима; фактически выполнен только первый блок из трёх.

[План 60 секунд](abc-dev-balanced.plan.json) — производный от прежнего плана с паузой
4 секунды. Порядок вариантов сбалансирован, между попытками — 60 секунд вне эпизода,
внутри попытки нет фиксированной паузы клиента; Retry-After соблюдается. Повторы
целого слота отключены до первых результатов B/C, чтобы A не занял весь лимит
последовательных сервисных сбоев. Предварительные два A сохранены отдельно.

[План 600 секунд](abc-dev-balanced-research.plan.json) зафиксирован после сервисного
отказа 60-секундного блока и до первых вызовов исследовательской серии. Он сохраняет
100 действий и те же данные, промпты, модель и порядок. Его нельзя объединять с
результатами в конкурсном лимите. Закрытые данные не использовались.

| Серия | Исходный коммит контроллера | Результат |
|---|---|---|
| Предварительная | `64cbf9711a23c86803797c0fd20ff646c1ccd882` | Два A: rate_limited и provider_error; остановлено контроллером при подготовке сбалансированного запуска |
| 60 секунд | `70a1ee1c0fc17a5183c00cdb50663f885ebd5c21` | Три rate_limited; автоматическая остановка после трёх сервисных сбоев |
| 600 секунд | `c67327e4133dbe9c8dc073d8fa7bd5109012ce12` | Три timeout; остановка по условию работоспособности |

Локальные deployment-планы дополнительно закрепляли ID Docker-моста и доверенный
прокси облачной среды. Их SHA сохранены в квитанциях; переносимые планы из Git не
выдаются за побайтовые копии deployment-планов. Использован изолированный Docker-мост,
проверка TLS включена, ключ передавался через окружение и в свидетельства не включён.

## Режим 60 секунд

| Вариант | Действия среды | Submit | Статус |
|---|---:|---:|---|
| A: исходный | 7 | 0 | rate_limited |
| B: общий метод аудита | 7 | 0 | rate_limited |
| C: метод и train-пример AuditLab | 12 | 0 | rate_limited |

В ответах провайдера зафиксирован HTTP 429 с `quota scope: minute`. Retry-After
58–59 секунд не помещался в оставшееся время эпизода. Это не сообщение об исчерпании
суточного лимита. После ожидания запросы снова проходили. У A также был HTTP 503.
Независимый скорер оставляет качество `F1=null, n=0` для каждого варианта; сервисный
отказ не выдаётся за финансовую ошибку модели. Механическая обработка пустых ответов
по правилу оценщика хранится отдельно.

## Отдельный режим 600 секунд

| Вариант | Действия без submit | Вызовы API | Время попытки, с | Записанные ожидания backoff, с | Сумма задержек вызовов API, с | Выполнение step среды, с |
|---|---:|---:|---:|---:|---:|---:|
| A | 34 | 45 | 601,601 | 498,000 | 90,965 | 0,0161 |
| B | 40 | 52 | 601,170 | 451,344 | 137,046 | 0,0102 |
| C | 47 | 58 | 600,837 | 478,000 | 109,779 | 0,0099 |

У всех статус `timeout`, submit отсутствует. Время попытки включает служебные расходы
запуска/завершения; дедлайн эпизода — 600 секунд. Backoff взят из `waited_s` журналов,
задержки API — из `latency_s`. В столбце среды только сумма `env_seconds` вызовов step,
без reset, IPC, создания и завершения моста. Эти величины не образуют полного
профилирования всего процесса; неразложенные расходы не приписываются модели или
финансовому ядру. Для B из 451,344 с backoff ровно 450 с относятся к Retry-After,
остаток — повтор после серверного сбоя.

Ожидания провайдера составляют примерно 75–83% времени этих попыток. Это подтверждает
существенный вклад внешних ограничений в задержки; не доказывает, что агент при другом
API обязательно ответит правильно или уложится в 60 секунд. Количество и выбор действий
тоже зависят от политики аудитора.

По установленному правилу timeout превращается в пустые findings. На данном эпизоде
независимый скорер получает для каждого A/B/C TP=0, FP=0, FN=1, F1=0. Это оценка
пустого ответа после дедлайна; ни один самостоятельный финансовый ответ аудитора не
получен. Ранжирование методов или эффект обучения из этих трёх исходов не выводится.

## Почему не запущены остальные 105 слотов

После тайм-аута A и **до итогов B/C** было отдельно записано условие работоспособности:
если первый полный блок A/B/C не даст ни одного отправленного ответа, остановить
массовую серию для диагностики. Это адаптивное операционное решение, а не исходная
регистрация завершённого бенчмарка. Условие сработало; stop_requested принят во время
паузы, следующая попытка не началась. Квитанция и решение сохранены в свидетельствах.

В каждом основном режиме выполнено 3 из 108 слотов, один эпизод и один повтор;
105 слотов не выполнены. Предварительные два A не добавляются к этому покрытию.
Всего в новом измерении восемь аудиторских попыток; отдельная проверка API-соединения
не считается аудитом. Лимит бюджета не был причиной остановки. Частично неизвестная
стоимость остаётся null; нулевые тарифы успешных запросов соответствуют заявленному
пользователем Free Tier, платёжный аккаунт этим измерением не проверяется.

## Свидетельства и повтор без API

[Каталог свидетельств](evidence/abc-live-2026-11-22/) содержит три раздельные серии:
`preliminary`, `official-60s`, `research-600s`. В каждой — квитанция, summary,
независимый comparison, ответы для скорера и ZIP с полными записями всех попыток:
наблюдениями, промптами, траекториями и журналом вызовов провайдера.
[Времена](evidence/abc-live-2026-11-22/timing.json) и условия остановки сохранены отдельно.

Из корня checkout с зависимостями из requirements.lock:

```sh
python review/agent_generalization/run.py compare \
  docs/research/agent-improvement-v2/evidence/abc-live-2026-11-22/official-60s/independent
python review/agent_generalization/run.py compare \
  docs/research/agent-improvement-v2/evidence/abc-live-2026-11-22/research-600s/independent
```

Повторный расчёт не вызывает модель. Сервисные ошибки, тайм-ауты и завершённые ответы
должны сохранять разные знаменатели.

Для продолжения нужен режим доступа к модели, на котором эпизоды завершаются при
соблюдении объявленного протокола: проверить квоту, задержки и число обращений, затем
зафиксировать новый запуск всех сравниваемых вариантов в одинаковых условиях.
Числа из прерванного запуска не заменяют отсутствующие результаты. Финальная закрытая
оценка и утверждение об улучшении остаются не выполнены.
