# Внутренняя репетиция

Команда запускает фактическую серию, а не заполняет строки ожидаемыми результатами:

```sh
python run.py verify --suite rehearsal --policy-image auditlab-policy:release --verifier-image auditlab-verifier:release --cpu-set 0,1 --output artifacts/rehearsal-candidate
```

Образы должны уже присутствовать локально. Проверка не скачивает их. При отсутствии
Docker или image обычная политика не заменяется незащищённым subprocess. Без
`--verifier-image` вычисление verifier идёт по отдельной public-копии на хосте;
это явно не считается проверкой его изоляции. `--cpu-set` должен соответствовать
доступным CPU хоста. Обычная политика и verifier получают лимит 2 CPU / 2 GiB;
лимиты доверенного процесса, общий расход хоста и пиковую память измеряет упаковка
релиза, не этот скрипт. Непроведённый замер памяти остаётся `null`.

В начале создаётся неизменяемый `rehearsal/selection.json`, затем фиксируется его
SHA-256. В нём 20 конфигураций/seed: ровно пять чистых, пять с взаимодействиями
обоих видов, десять одиночных/смешанных. Есть валюты с разрядностями 0/2/3,
разные размеры до 2000 проводок/200 документов, весенняя и осенняя смена часового
пояса New York. Конфигурации используют версию генератора `1.1`.

Это открытая внутренняя проверка регрессий, **не скрытые данные организаторов**.
После просмотра результата её нельзя называть новым отложенным набором при
сравнении настроенных на ней политик. Секретность seed не является защитой.

Для каждого эпизода:

1. Генератор создаёт снимок и его повтор; проверяются полные хеши файлов.
2. Отдельный verifier получает только шесть файлов public. Его ответ записывается
   до чтения эталона сравнивающим кодом. При `--verifier-image` файлы передаются
   по stdin в контейнер без сети/томов; путь к private и seed ему не передаются.
3. Проверяются типы/количество ошибок, независимое совпадение и адресуемость всех
   доказательств через настоящие публичные инструменты. Проверка по известным ID
   отдельно обозначена и не подменяет поиск обычным аудитором.
4. На одном снимке выполняются random, reconcile, flag_all и доверенный oracle.
   Три обычных политики изолированы в Docker, oracle остаётся на доверенной стороне.
   Режим — closed: в сохранённой агентской траектории награда нейтральна, настоящая
   оценка находится только в доверенном отчёте.
5. Строится новая компания с взаимно однозначно заменёнными ID и перестановкой строк.
   Независимый ответ должен совпасть после отображения ID. Oracle проходит настоящий
   reset/step и должен получить те же TP/FP/FN и награду при одинаковых инспекциях.
   Проверяются новые ссылки и повтор исходной записи действий reconcile (если он
   успешно сдал ответ), иначе явно помеченный повтор oracle в свежей среде.
   Повтор сравнивает публичные переходы и доверенный отчёт: оценку, настоящую
   награду, статусы, шаги и версии. Нейтральная публичная награда в closed-режиме
   не подменяет сравнение настоящей оценки. Время и идентификатор попытки исключены
   из детерминированного сравнения; без исходного доверенного отчёта повтор не проверен.

Все 80 попыток и 20 пар остаются в знаменателях. Неудачный аудит с низкой наградой
отличается от сбоя политики, инфраструктуры, усечения и непройденной проверки данных.
Для сбоя не выдумывается нулевая финансовая оценка. Сводка указывает число измеренных
эпизодов, micro P/R/F1, macro F1, награды, распределение шагов/времени, полноту по
классам и ложные обвинения на чистых случаях с явным знаменателем.

Результаты лежат в `rehearsal/report.json`, `attempts/`, `independent/`, `pairs/`;
`selection.json`, карты ID, снимки, ответы и траектории позволяют повторить конкретный
сбой. Отчёты обновляются атомарно; существующий каталог попытки не перезаписывается.

Успешная репетиция не присваивает себе баллы жюри и не закрывает автоматически
24 группы SPEC. Поэтому общий отчёт остаётся `incomplete`/код 2, пока не выполнена
отдельная полная приёмка, включая реальную изоляцию, офлайн-поставку и измерения ресурсов.
Ошибка данных/теста/политики/инфраструктуры даёт код 1. Это ожидаемое различие между
измеренной внутренней серией и готовностью всего релиза.
