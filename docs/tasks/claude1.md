# Claude Pro 1 — Оценщик, контракт reset/step и изоляция раннера

Ветка `feature/evaluator-runner`. База и цель PR — `main`.

**Вход.** Прочитать [ТЗ](../SPEC.md) §§3, 7–9, 11–12, 14–15 и [контракты](../INTERFACES.md). Запустить `python -m unittest discover -s tests/foundation -v`.

**Владение.** auditlab/evaluator/, auditlab/runner/, tests/evaluator/, tests/runner/, docker/runtime/.

## Задачи

1. Реализовать строгую проверку submit, сопоставление максимальной мощности, TP/FP/FN, F1, стоимость осмотров и отдельный доверенный oracle.
2. Собрать публичный фасад reset/step, таймер, завершение, передачу публичных осмотров в PublicSession и сдачи оценщику; выпускать JSONL-траектории и экспорт завершённых открытых опытов.
3. Обеспечить отдельный процесс/изоляцию политики, публичный канал и скрытую диагностику; подготовить исполнимые runtime-образы/инструкции для упаковщика GPT Pro 2.
4. Сначала использовать готовую fixture и подставной PublicSession; после первого PR GPT Pro 1 подключить настоящий модуль через публичный интерфейс.

## Приёмка

Чистая сдача, дубли, чужие/альтернативные доказательства, 99 осмотров + submit, 100-й осмотр, тайм-аут и закрытый режим дают ожидаемые результаты. Обычная политика не получает truth.

В PR укажи команду воспроизведения, пройденные и непройденные проверки, влияние на контракт и зависимости. Свяжи PR со своей GitHub Issue, если она опубликована. Открывай PR в main. Итоговое слияние выполняет GPT Pro 2 после проверки.
